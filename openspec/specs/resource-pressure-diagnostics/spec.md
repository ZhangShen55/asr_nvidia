# resource-pressure-diagnostics Specification

## Purpose
定义 ASR 服务在本地模型、VAD worker 和多路音频并发下的资源压力观测、受控验证和归因报告能力，帮助运维在发生 Swap、显存不足或请求卡顿前停止升压，并为后续内存释放、队列调度和实例规模优化提供证据。

## Requirements

### Requirement: 采集统一资源快照
诊断工具 MUST 以统一时间戳采集 SeaCraftASR、VAD worker、本地转写模型、主机内存、Swap、NPU 设备资源、线程、文件描述符和服务缓存状态，并保存可复算的结构化记录。

#### Scenario: 采集运行中快照
- **WHEN** 诊断测试正在处理请求
- **THEN** 记录后端 PID 存活状态、VAD worker 数量、RSS/PSS、`VmSwap`、`MemAvailable`、Swap 增量、NPU HBM 占用与利用率、缓存文件数量和端口健康状态

#### Scenario: 区分模型与请求资源
- **WHEN** 模型加载、音频并发或段级并发发生变化
- **THEN** 快照能按测试阶段关联模型池实例、模型池等待、请求数和资源峰值，不能只记录进程总 RSS

### Requirement: 按阶段受控升压
诊断测试 MUST 按所选协议分阶段验证模型单独/同时驻留与真实并发，已确认正常的独立VAD-only项不重复升压；完整音频请求内VAD不得跳过。历史2/4/8档仅在显式legacy专项适用，不作为新continuous默认门槛。本次最终剩余流程按2026-11-24用户决定为N4/CAM4/emo1实例覆盖、同源a1～a4的B4及增强共驻A4；已执行N6 A6/A4/B4、共驻OOM和N5补测保留历史；前阶段未安全收尾或触发失败门槛 MUST NOT 进入下一阶段，不借本轮完成旧未验收矩阵。

#### Scenario: 逐级进入下一阶段
- **WHEN** 当前阶段所有请求完成且冷却期间资源指标保持稳定
- **THEN** 测试控制器才允许启动下一档并发，并保留当前阶段的配置和结果

#### Scenario: 阶段失败停止升压
- **WHEN** 当前阶段出现资源红色告警、后端异常或请求失败门槛
- **THEN** 控制器停止发送新请求，不再重试同一压力档位，并将该阶段标记为失败

#### Scenario: 独立增强池逐池标定
- **WHEN** 用户在原N6/N5瓶颈和共驻证据后明确采纳最终四Qwen/CAM4/emo1，准备验证B4
- **THEN** 对该确定组合记录每池真实等待、调用、HBM和冷暖，完成后保持同一模型驻留验证同源A4；不再盲扫组合或按N复制增强池，异常停止而不自动换档重试

### Requirement: 执行资源安全闸门
诊断测试 MUST 设置清晰告警与终止条件；正式多实例轮次保留336秒、实际OOM、owned故障及明确无进度停止并采证，触发后停止当前批及后续压力，安全收尾后先诊断。MUST NOT 使用free-HBM<8GiB或任何替代剩余HBM阈值提前停止本轮，但持续采集真实HBM及故障；既有主机Swap/内存安全约束保留。仅可收尾本次独立拥有的资源，MUST NOT 停止共享服务；内嵌模型随所属测试实例统一关闭。

#### Scenario: Swap 或内存压力终止
- **WHEN** 测试期间 Swap 增量超过阈值、`si/so` 持续非零或可用内存低于安全水位
- **THEN** 测试立即停止升压并终止当前批次，保存终止前后的资源快照和日志

#### Scenario: GPU 或进程异常终止
- **WHEN** 本次正式多实例验收出现OOM、后端健康检查失败、owned模型进程或VAD worker异常退出、明确无进度，或当前批达到336秒终止条件
- **THEN** 测试停止提交请求，保留现场信息并确认 SeaCraftASR 进程树、端口和缓存状态可回收

#### Scenario: 剩余HBM降低但未发生故障
- **WHEN** 正式验收观察到free-HBM低于8GiB但没有其它真实故障或已定义终止条件
- **THEN** 记录时间序列、告警及外部占用，继续按当前协议运行；不恢复已取消的8GiB提前线，不更换另一个free-HBM阈值，也不把不可观测值填零作为停止依据

#### Scenario: 接近历史420秒的停测边界
- **WHEN** 正式性能轮达到336秒或实际OOM、owned故障、明确无进度条件
- **THEN** 停止当前批和后续升压并保存已完成与未完成请求状态，等待真实设备及分支安全终态；不自动降配重试来替代本轮失败证据

### Requirement: 保留请求和模型池关联指标
诊断结果 MUST 按request_id记录请求起止、耗时、码、警告、重试和有效段数，关联固定owner及Qwen/CAM/emo等待与执行。分列configured N、healthy H、leased/closing和有效B容量，故障收尾占用不得伪释放。阶段计时包含解码准备、VAD、裁剪及线程等待、租约、提交/prefill/decode/读回、分支汇合、聚类、ITN和输出；未独立测量须标unknown，不跨owner累计相加解释墙钟，保持v3 gpu_time_ms原契约。

#### Scenario: 定位请求落后环节
- **WHEN** 某批次的 p95 明显高于 p50
- **THEN** 报告能比较 Qwen 等待、CAM++ 等待、emotion2vec 等待、VAD、裁剪和总耗时，指出主要排队位置

#### Scenario: 时长skip与真实增强执行分开
- **WHEN** B4同时请求说话人与情绪，部分有效段不满足emo的1～10秒含边界时长条件
- **THEN** 分别报告CAM/emo实际调用、成功、失败、skip和池等待；时长外平淡不算NN推理成功，空embedding和增强降级明确单列，并核验每个配置实例真实被调用

#### Scenario: 故障owner仍在关闭
- **WHEN** 健康owner数下降但故障请求的设备或PCM分支尚未安全终态
- **THEN** 状态保留该request_id的leased/closing占用，H只约束新准入与状态，不通过清零旧计数或将closing冒充健康可租owner制造容量

### Requirement: 输出资源压力归因报告
报告 MUST 区分模型常驻内存、音频与段级缓冲增长、请求后未释放、Swap 换页和 NPU 算力争用，并给出对应的后续优化方向和安全并发建议。

#### Scenario: 模型常驻内存过高
- **WHEN** 单路完整模型阶段已接近内存安全水位
- **THEN** 报告建议减少实例、拆分设备或增加内存，并明确并发升压不是解决方式

#### Scenario: 并发缓冲或释放异常
- **WHEN** 单路稳定而多路阶段内存随并发增长，或连续请求后 PSS 持续增长
- **THEN** 报告分别指向在途音频/段缓冲、对象引用或缓存清理方向，不将其误判为模型权重增长

#### Scenario: GPU 算力争用
- **WHEN** 主机内存和 Swap 稳定但 NPU 利用率长期饱和且模型等待增加
- **THEN** 报告将问题归因于同卡算力争用，并建议调整实例数量、设备分配或模型调度

### Requirement: 测试结束后验证回收
每阶段结束 MUST 验证请求/设备排空、窗口及私有PCM归零；计划内连续共驻阶段保持健康服务及模型驻留。测试服务生命周期结束或出现失败、取消、中止、部分启动失败时 MUST 关闭全部owned服务、代理、N份Qwen、增强池、VAD及测试容器并验证端口与资源回归。启动登记PID/birth及后代，重复取消不遗弃收尾，升级仅限复核归属的资源，MUST NOT 按端口/名称误停共享服务。正式验收要求正常退出、端口连续空闲≥5秒、私有PCM为空及共享PID1601397保留；强杀兜底、超时或退出1不得记正常回收。日志与报告保留，不以删临时现场代替关闭证据。

#### Scenario: 正常阶段结束
- **WHEN** 一个阶段的全部请求完成
- **THEN** 记录冷却期资源值、缓存差值、进程树和端口状态，确认所有owner的段窗口及PCM恢复基线后才允许下一阶段

#### Scenario: 异常阶段终止
- **WHEN** 红色安全闸门终止阶段
- **THEN** 保存终止现场，停止后续测试，并确认没有继续向已异常的后端发送请求

#### Scenario: 测试批次完成后释放接口
- **WHEN** 本次测试服务的全部计划批次成功结束，或任一批次失败、取消、中止而终止后续测试
- **THEN** 统一收尾路径等待已启动工作完成，关闭本次拥有的服务及子进程；以启动登记PID/birth及后代和监听表交叉核验正常退出、测试端口连续空闲至少5秒、私有PCM为空、无孤儿或自动重启，保存退出码和NPU回归相近背景证据；TIME_WAIT不视为残留监听，共享PID1601397及其原端口保持原状

#### Scenario: 关闭流程自身被重复取消
- **WHEN** 本次测试实例已经进入关闭流程，收尾等待中再次收到取消
- **THEN** 收尾任务不被遗弃，完成进程退出及监听释放核验后传播取消；无法在界限内完成则按关闭失败处理并保留证据，不标记验收完成

#### Scenario: 测试服务关闭失败
- **WHEN** 等待时间已到且本次测试服务或监听端口仍未释放
- **THEN** 记录残留进程/端口归属并只对已确认的测试资源按约定升级处置；收尾未成功时报告失败，不把验收或归档标记完成，不误停共享服务

#### Scenario: 强制兜底不能充当正常关闭
- **WHEN** 服务超过模型grace120秒、外层210秒或HTTP drain30秒等规定收尾界限而需强制处置，或有owned进程退出1
- **THEN** 仅处置再次确认归属的测试资源并保存异常证据，正常关闭验收标未通过；不能因最终端口消失、HBM下降或强杀成功勾完成

### Requirement: 转写推理资源必须纳入诊断归因
由于转写模型已内嵌服务进程，诊断报告 MUST 把转写推理耗时与本地模型池等待、音频准入等待分开统计，MUST NOT 把转写推理的设备算力等待归入其它环节。

#### Scenario: 定位转写推理瓶颈
- **WHEN** 某批次的 p95 明显高于 p50
- **THEN** 报告能比较转写推理耗时、模型池等待、音频准入等待、VAD 与总耗时，指出主要排队位置

### Requirement: 共享设备与异步执行的诊断边界明确
诊断 MUST 记录物理卡、可见逻辑卡映射、其它进程占用和测试实例归属。阶段切换及资源回收验证 MUST 等待设备工作与必要清理完成，不能以客户端断连或线程返回代替。资源不可观测时 MUST 标记未知及原因，不能填零当作无占用。

#### Scenario: 在共享物理7号卡压测
- **WHEN** npu:7 已有非测试 uvicorn 或其它进程
- **THEN** 记录其资源占用与测量期间的竞争，不停止其进程；报告把共享干扰与模型自身性能区分，结果不宣称独占卡最佳性能

#### Scenario: 归因内部耗时
- **WHEN** 比较原生 eager、编译或微批的瓶颈
- **THEN** 内部记录模型加载、首次编译、重编译、批等待、实例等待、实际完成的设备执行与端到端耗时；保持 v3 gpu_time_ms 原契约，不用新增诊断口径覆盖它

### Requirement: 正式多实例采用真实完整接口验收矩阵
正式continuous最终验收 MUST 使用改造后的正式源码、单HTTP服务、N4/S16/global64/npu7及CAM4/emo1最终配置，通过v3真实HTTP处理原a1～a4完整WAV的B4及全部模型驻留后的纯A4；同源纯A4基线、准入与暖身证据分列。原N6 A6/A4/B4、共驻OOM及N5补测保留，不用N4宣称N6通过。MUST 保存清单SHA/路径字节、源码/配置/实际导入与依赖身份，不预切段、替换短文件或用实验194.81秒替代。所有Qwen有真实暖身、所有增强实例有真实调用，冷加载与暖性能分列；旧八路未验收矩阵不在本轮冒充完成。

#### Scenario: 从正式入口完成最终N4完整音频轮
- **WHEN** 最终部署为continuous/process、N=4、S=16、CAM4/emo1及npu7，四Qwen已健康并分别真实暖身，窗口和PCM归零
- **THEN** 原a1～a4从真实v3 HTTP共同起跑且独立租owner，计时包括请求内VAD/裁剪及全部处理，保存4份完整或删失响应和每owner≤16/合计≤64、独立补位证据，不用组件重放代替

#### Scenario: 同源A4与双增强B4
- **WHEN** 最终四份Qwen驻留，依固定a1～a4的纯A4基线，以CAM4/emo1配置执行showSpk=true、showEmotion=true、showRoleIdentify=false的B4
- **THEN** 保留两轮独立完整响应、各池实际执行/等待和真实说话人/情绪字段，逐段对照文本归属；总容量/B容量探针另轮执行且结束归零，不将不同N/模式/驻留条件的墙钟直接当增强开销；N4总4/B4同时满时新A/B均4013，不能要求单独触发4017，原N6探针历史保留

#### Scenario: 所有模型共驻后复验纯转写
- **WHEN** 最终N4/CAM4/emo1的B4完成且全部模型保持驻留，随后再次请求同a1～a4纯A4
- **THEN** 验证完整4/4、无OOM/owned故障、实际效率/HBM及正常关闭，和此前纯A4、N6/N5结果分开；最终loader/根/Docker/说明与验收快照一致，不能用小池成绩交付未测高池数，也不冒称原N6共驻通过

### Requirement: 正式多实例性能和质量采用完整统计口径
报告 MUST 区分功能、性能目标、质量警告及正常关闭。纯A约200秒为单列目标，不作保证，N6历史A6与最终增强驻留A4各据实报告；B4无200秒硬门槛，按真实耗时报告。每轮报告完整n/N、业务成功与严格无警告成功、全部警告/丢弃、P50/P95/墙钟及删失；未完整完成全批分位数未知。MUST 输出同源完整文本及边界/角色/情绪的具体差异；没有人工真值不得认证绝对质量，不能用相似度或HTTP200掩盖未完成、警告和增强降级。

#### Scenario: 完整批次报告独立分位数
- **WHEN** 同一配置和状态的最终A4/B4或增强驻留A4全部返回完整响应（N6/N5历史独立保留）
- **THEN** 逐请求从HTTP发送至完整响应接收计时，以首请求发送至最后响应接收计算墙钟，另列最大请求耗时；P50/P95按线性插值并注明实际n（最终为4，历史N6为6、N5为5）和冷暖状态，不混合不同轮次

#### Scenario: 终止时存在未完成请求
- **WHEN** 当前轮停止或取消时只有部分请求完成
- **THEN** 全批P50/P95明确unknown，仅另列完成子集n及其分位数，保存未完成/失败/取消名单和观察时点；不能把取消后未返回全部视为慢于336秒，也不能将子集成绩当完整验收

#### Scenario: 警告及增强降级不能算严格成功
- **WHEN** HTTP200结果包含completed_with_warnings、不可恢复丢弃段、CAM空embedding或增强异常降级
- **THEN** 将业务完成与严格无警告/增强完整成功分开计数，列出具体段及动作；纯A即使完整返回也独立报告200秒目标是否达成，B4不能仅凭HTTP200判真实双增强通过

#### Scenario: 列出具体输出差异和质量限制
- **WHEN** 比较历史正式A6与同源六音频noHBM参考，或比较最终固定a1～a4的A4/B4及增强驻留A4输出
- **THEN** 保存全部文本与段结构，逐段列实际变更内容、遗漏/新增、边界/说话人/情绪及warning差异，保留不可对齐项；未有人审真值时质量未认证，不承诺绝对准确率或98%召回，也不以历史实验成绩替代正式证据
