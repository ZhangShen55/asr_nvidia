# 910B 迁移测试计划

本文件将既有测试任务收敛为可执行的分层验收矩阵，补充故障、微批及稳定性覆盖。全部硬件验证使用 `xjtu910b7` 的 conda `asr` 和宿主 `npu:7`，重建性另在独立前缀验证。当前已进入 apply；实际结果、日志及未执行项以迁移报告和 tasks 复选框为准，矩阵本身不代表通过。

## 1. 执行顺序和证据

1. 冻结当前 v3 请求/响应、默认值、错误码及后处理参考，登记样本和数值容差。
2. 在无硬件初始化的替身环境运行逻辑单测，随后在目标 asr 环境运行迁移后的完整 `python -m pytest tests/`。
3. 使用真实权重逐模型验证 VAD、CAM++、emotion2vec、Qwen，区分首次加载与预热后运行。
4. 运行短样本、真实课堂长录音及功能开关矩阵的 v3 端到端回归。
5. 验证故障、取消、微批归属和稳态资源，最后按候选后端和并发档位做性能验收。

每层报告记录模型/processor revision、Python/依赖/CANN/驱动、配置、设备映射、样本 ID/SHA256、命令、日志和通过/失败/未执行原因。安装元数据、文件存在和桩测试不能替代真实前向。CPU 单测可标记硬件用例未运行，但最终 NPU 验收不能把 skip 当通过；候选未采用或在目标栈不支持时记录不适用原因，不伪造覆盖。

## 3. 故障和取消矩阵

逐项覆盖：音频准入等待、VAD 排队/执行、首次 Qwen 加载锁等待、段级/全局信号量等待、实例排队、实际设备执行、结果读取、实例释放与关闭。对已启动异步/线程/设备工作的阶段验证取消与重复取消，其余阶段验证取消不会发起新工作或泄漏排队名额。

- 模型目录缺失、不可读或 checkpoint 不匹配使用独立测试配置/临时资产或替身模拟，不移动、截断、改权限或破坏用户原始权重。
- OOM、设备异常、生成超时和清理异常优先用受控故障注入；不在共享卡故意耗尽 HBM，不停止既有 uvicorn。
- 实际 NPU 冒烟需覆盖本项目独立实例的正常请求、有限在途取消和排空，不能只依赖 fake device；测试只关闭自己持有生命周期的实例。
- 对无法安全在真机复现的故障明确记录“替身覆盖，未进行破坏性实机注入”，不能冒称硬件故障已复现。
- 所有阶段检查错误归属、失败实例容量、其他健康实例结果及最终计数，不能仅断言 HTTP 请求结束。

## 4. 数据与质量门槛

现有 52 WAV/2 MP3 先建立清单，并确认是否包含同一录音的不同编码或副本；文件头约43.66小时只统计 WAV，不计为完整解码或标注完成。短回归片段可从原音频只读提取到测试专属输出目录，记录来源时间段及哈希；覆盖教师/学生、方言、低音量、噪声/静音、中文/英文/混合语种，并注明每类实际可获得的样本，不能从文件名直接推断真实标签。

预先固定代表性回归集和独立验收集，同源片段不得被当作相互独立的调参/验收证据。有人工参考时可报告 WER/CER、有效发言召回、聚类和情绪质量；无参考时只报告差异和人工抽查范围，不宣称准确率达标。若评估有效对话召回，遵守项目已有 ≥98% 门槛；其它数值容差和性能预算先在报告登记，不能为通过某后端而在最终验收后追改。

## 5. 稳态资源和最终门槛

先记录独立测试实例预热后基线，再按固定配置连续请求；预先登记轮次/持续时间、冷却窗口和允许波动依据。区分 PyTorch allocated/reserved、进程与设备 HBM；预热缓存不是自动判定泄漏的理由，无法归因时明确未知。阶段排空后确认活动/等待计数、租约、临时文件、线程/FD和 worker 生命周期；测试批次完成或中止后必须对本项目独立实例执行关闭并核对进程和端口回收，不再将关闭作为可选步骤。

最终报告逐项关联任务、用例、命令和日志，并明确通过/失败/未执行/有依据的不适用。完整逻辑回归、适用的四模型真实前向、v3端到端、取消收尾和目标并发验收均须有证据；尚未运行、缺少权重/参考或仅skip的必需项不得算通过，也不得归档为完成。候选优化失败可以有依据不采用，但不得省略原生交付路径的验收。

实际镜像构建与上线仍后置；本计划中的容器/构建静态契约检查不表示容器已启动或上线成功。

## 6. 测试结束必须关闭服务并释放端口

- 启动前记录本次 run ID、服务主 PID及进程创建信息、进程树/容器、监听地址和端口，并确认所选测试端口未被既有服务占用。只对本次明确持有生命周期的资源执行关闭。
- 同一测试批次内为连续测量可以复用服务；批次成功、失败、取消或中止时，统一通过 finally/等价 teardown 停止接收请求，等待在途线程/NPU工作及必要清理结束，再关闭本次启动的 uvicorn、代理、候选推理引擎、VAD worker 和测试容器。
- 收尾自身收到取消或重复取消时，延迟向外传播并等待独立收尾任务完成或按有界超时策略报告失败；补充“关闭中重复取消”的用例，确认不会因 finally 内等待被取消而遗留服务。
- 测试启动失败也要回收已成功启动的部分资源。测试自身的自动重启/守护设置不得在收尾后重新拉起接口；不得留下后台服务供“以后继续测试”。
- 预先登记合理的收尾等待时间；超时先保存诊断，只对再次确认身份和归属的测试实例按约定升级终止，不能仅凭旧 PID、端口号或进程名批量关闭共享服务。
- 结束后用进程树和监听表（如 ss/lsof 等适用工具）交叉核对：本次服务和子进程已退出、无测试孤儿 worker、测试拥有的端口不再 LISTEN，并在登记的观察窗口内未重新出现。连接进入 TIME_WAIT 不等于仍有服务监听，不要求通过破坏正常TCP收尾清空该状态。
- 保存关闭前后进程、监听表、在途计数及资源记录，保留测试日志/报告；卡 7 既有 uvicorn 和其它共享进程继续存在不属于测试泄漏，不以全卡 HBM 为零作为关闭标准。
- 关闭失败或测试端口仍被本次实例监听时，明确报告失败和残留归属，不能把整批测试标为验收完成。对应实施任务为 11.6。
