# Design

## Context

已有分离的容器运行环境与模型命名上下文。独立 Cython 保护脚本要求 Python3.10/aarch64 和已标记 staging，编译后剥离业务源码。

## Goals / Non-Goals

- 让默认 Docker 构建生成保护运行镜像，保留必要的可读启动文件。
- 保留原生部署与已部署容器。Cython 属于编译保护，扩展仍可被逆向。

## Decisions

1. 独立 stage 从同一重定位解释器复制环境。固定 Cython 源码包 仅在此阶段从命名上下文读取。继续复用现有 Cython 语义开关和 staging 防护。
2. 源码和生成 C 文件仅存在于构建阶段。只有经过文件范围和准确 ABI 后缀校验的产物进入最终层，扩展去除调试和非必要符号。
3. 保持主入口的进程信号、配置读取和子进程导入路径。默认使用独立保护标签，既有源码标签保留。
4. 实际镜像检查内容及中间层，使用普通运行入口验证配置门禁，在禁用 NPU 的隔离容器中验证扩展导入与序列化。完整实机验收需要可用卡和独立运行窗口。

## Risks / Trade-offs

Cython 编译可能改变 introspection 和 multiprocessing 行为。以实际运行层导入路径和既有保护模式回归检查。运行镜像不会携带编译器安装步骤或工具源码包，底座自带工具按原底座边界说明。
