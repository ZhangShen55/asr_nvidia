# Design

## Context

动机见 `proposal.md`。当前 `core/qwen_asr_queue.py` 的 `AudioSlotManager` 只有活动总数和等待总数，由进程内单例管理；`RequestConcurrency` 则独立限制单音频段数和全局 Qwen 调用数。v2 路由先取得音频名额，再准备音频、执行转写、清理临时文件，最后释放名额。

当前 `run_qwen_asr` 已通过 `showSpk OR showRoleIdentify` 判断是否需要 CAM++，但 `load_v2_models_if_needed` 在功能关闭时仅跳过加载。后续段级函数仍可进入模型池租用流程，重新触发加载。只修改加载分支不足以保证功能开关生效。

主规格和 README 的部分旧条款把配置关闭描述为成功返回 `null`，与本次已确认的错误响应冲突。本 change 的增量规格完整替换这些相关条款；模型已开启且存在健康实例时，普通段级推理失败仍保留原有 `null` 回退。

状态组装目前同步读取快照，遥测最多保留 4096 条事件，近期明细最多 20 条。新增指标沿用这两条路径，不引入外部监控依赖。项目已有 `tests/test_qwen_v2.py`、模型池及状态测试，可使用桩验证，无需真实模型或 Qwen 服务。

## Goals / Non-Goals

**Goals:**

- 把整音频准入、段级 Qwen 并发和模型池推理容量保持为三个不同层次。
- 在单个服务进程内原子维护总音频与 B 音频计数，以可追踪租约明确名额所有权。
- 明确等待公平性、错误优先级及取消竞争行为，避免实现时重新决定对外契约。
- 对功能开关实施路由准入和模型运行入口两层校验。

**Non-Goals:**

- 不增加跨进程或跨部署的分布式计数器，不改变 `instance_count` 语义。
- 不调整 VAD 算法、设备数组、Qwen 信号量、说话人聚类或情绪推断策略。
- 不新增共享的段级模型推理闸门，也不推进其他 change 中的 FireRedVAD 或 TensorRT 工作。
- 不处理与本次准入及生命周期无关的历史测试和角色标签问题。

## Decisions

### 1. 集中解析请求能力，先校验开关再准入

在现有 v2 共用模块中提供无副作用的能力解析函数，供路由和转写入口复用：

```text
need_role = bool(showSpk or showRoleIdentify)
need_emotion = bool(showEmotion)
category = B if need_role or need_emotion else A
```

`entity/data.py` 已将三个参数默认设为 `false`，保留其数据类、表单和 OpenAPI 默认值。分类由请求要求决定，不依赖某段长度、有效段数、模型设备数量或模型当前是否已加载。

路由顺序为：保留已有 Qwen 总开关校验 → 解析请求能力 → 校验增强开关 → 获取音频租约 → 准备音频并运行链路 → 清理 → 释放租约。FastAPI 自身的表单解析和参数校验不属于音频预处理。

`core/models.py` 提供共享能力校验，先计算全部被请求但关闭的能力，再选择错误，避免先加载一个模型后才发现另一个关闭。扩展现有不可用错误的组合分支，但 `4018` 仅表示本次请求同时需要两项、且两项配置均关闭，不扩展为所有双模型运行失败的通用代码。

| 所请求的关闭能力 | 返回码 | 行为 |
| --- | --- | --- |
| 只有说话人 | 4015 | 返回现有 CAM++ 不可用错误 |
| 只有情绪 | 4016 | 返回现有 emotion2vec 不可用错误 |
| 同时请求说话人和情绪，两项都关闭 | 4018 | `CAM++ 与 emotion2vec 能力均未启用` |
| 没有请求被关闭的能力 | 继续 | A 或 B 正常准入 |

两项均关闭但只请求一项时，仍返回对应单项错误。`showRoleIdentify=true` 等同请求说话人能力。错误保持 HTTP 200 和既有 `msg/code` 格式。

模型运行入口也校验功能开关：`load_v2_models_if_needed` 在任何加载前校验完整需求；真实模型池在加载及租用前检查对应开关，即使池内已有句柄也不得使用关闭能力。增强链路的入口校验早于段级异常回退和情绪时长快捷分支，不能把配置关闭吞成 `null` 或普通情绪值。

采用该方式是因为仅在路由校验会遗漏直接调用运行链路，只有池内校验又会在音频准入后浪费总槽位并可能被段级异常捕获。设备数组仍描述候选实例，不能充当功能开关。

### 2. 单管理器维护两个容量，使用不可变分类租约

扩展 `AudioSlotManager`，保留进程内单例，在同一临界区维护：

```text
total_limit = settings.qwen_audio_concurrency
b_limit = settings.qwen_audio_spk_emo_concurrency
active_total = active_A + active_B
0 <= active_B <= b_limit
0 <= active_total <= total_limit
```

A 取得一个总槽位；B 在同一临界区检查两类容量并同时增加两个计数。不串行获取两个独立信号量，也不让等待 B 持有部分资源，否则会阻塞本可运行的 A，并增加取消时的回滚分支。

`acquire(category)` 返回租约，记录唯一标识、不可变 A/B 分类及释放状态；释放以租约为依据，不能由调用方重新推导请求分类。管理器只保留当前活动租约的有界登记；重复释放不得扣减其他请求的名额。A/B 活动计数、等待变化和授予动作均在一个锁内完成，计数不能出现部分更新。

对无等待的默认模式，先判断总容量，再判断 B 容量：

| 条件 | code | msg |
| --- | --- | --- |
| 总活动容量已满 | 4013 | `处理队列已满，请稍后再试（当前音频并发：8/8）`，比值取当前值 |
| 总容量有余量，仅 B 容量已满 | 4017 | `spk_emo队列已满，请稍后再试（当前增强音频并发：4/4）`，比值取当前值 |
| 等待模式的共享等待队列已满 | 4013 | `服务繁忙，请稍后再试` |
| 等待超时 | 4010 | `请求排队超时，请稍后再试` |

能力校验在这些判断之前。等待模式下容量暂时不足会进入等待，而非立即返回 `4017`；等待名额不足返回 `4013`，截止前未取得完整名额返回 `4010`。遥测另行区分总容量满与共享等待队列满。

### 3. 两类逻辑 FIFO，按最早可处理请求调度

保留一个共享 `queue_max_size`，维护 A、B 两个逻辑 FIFO，每个等待者有全局单调递增的入队序号、类别和截止时间。调度前移除已取消或已到截止时间的等待者，调度时只比较两类队首中当前满足全部容量条件的候选，选择序号更小者，授予后重复调度直至无候选。

这样同类顺序明确，并能跳过因 B 上限阻塞的 B。严格混合 FIFO 会使 `3A+4B` 加一个等待 B 的情况下空闲总槽位无法接收 A；无顺序的条件变量唤醒则无法保障较早 B 在有资格后优先。

新请求在同一临界区先推动已有可处理等待者，再判断能否立即接收。若已有等待 B 仅因 B 容量满受阻，新 A 可直接使用总容量，即使等待队列已达到上限也无需额外等待位置；但不能越过已满足条件的较早请求或同类队首。

等待总数等于 A+B 等待数。B 等待时不增加任何活动数；超时、取消、移出等待转为活动时都准确回收等待位置。`queue_max_size=0` 表示不能等待，仍允许有资格请求直接获准。

该调度保证有资格的较早请求不被后到请求抢占，不承诺完成耗时相等或按提交顺序完成。B 已满时让 A 利用剩余总容量，不为 B 预留总槽位。

### 4. 明确授予、移交和清理的所有权

租约从准入成功覆盖音频准备、VAD、Qwen、CAM++/emotion2vec、后处理和临时文件清理。准备失败、返回业务错误、普通异常和取消均走统一收尾路径。等待不持有活动名额；被能力校验拒绝的请求也不进入等待。

等待者状态采用明确的 `WAITING → GRANTED → RELEASED` 转换，另有等待阶段的超时/取消终态：

- 授予时由管理器拥有租约，活动计数已增加，等待计数已移除。
- 获取协程成功返回前完成所有权移交；若取消发生在授予后、调用方收到租约前，由管理器回收已经授予的租约。
- 调用方的最外层 `try/finally` 覆盖获取动作，并仅释放实际取得的租约。成功返回与租约变量赋值之间不引入额外异步等待。
- 超时与授予竞争由同一状态检查收敛到一个结果：返回完整租约，或回收后返回 `4010`。不能通过取消 Future 后只扣减等待数来处理所有情况。
- 清理失败不能跳过租约释放；释放及取消回收保持幂等，双计数始终一起变更。

取消收尾需要保留并等待完成的清理任务，再传播原始取消；仅对释放调用 `shield` 然后立即退出并不能证明名额已回收。对已经启动且无法由协程取消停止的本请求线程任务，等待其结束后再释放相应模型租约及整音频租约，防止计数显示空闲但推理仍运行。此处只调整本请求的任务收尾，不改变模型池容量或推理算法。

现有 `prepare_asr_context` 在失败时清理部分创建的临时文件；路由同时保留已返回 context 的统一清理。验证准备失败和取消中断时的部分文件登记，补齐必要的 `finally`，不遗漏尚未返回 context 的文件。清理动作完成必要尝试后才释放租约，无法删除的路径按现有日志策略记录。

### 5. 新配置缺省为 4，严格校验且不截断配置

`core/config.py` 增加 `qwen_audio_spk_emo_concurrency`，只接受 TOML 正整数，明确排除 Python 中属于整数子类的布尔值；拒绝 0、负数、浮点数和字符串。在服务就绪前读取校验，不依赖首个业务请求才暴露错误。

缺少字段固定采用用户确认的 `4`，不使用总容量作为兼容回退。允许 B 上限大于总上限，两条约束共同使实际 B 上限为 `min(total_limit, b_limit)`，状态保留原始配置值；这也使总容量配置为 1 或 2 时默认 B=4 仍有效。相比把 B 静默截断为总容量，如实报告配置更利于运维理解。

在 `config.toml` 与 `config.docker.toml` 增加同名字段及 A+B/B 注释；保留本地配置已有的设备、功能开关和其他定制值。参数按现有机制随进程启动读取，不实现热更新。每个实例维护独立限制，多实例部署没有跨进程总额承诺。

### 6. 状态读取一致快照，遥测沿用有界历史

管理器提供一次生成的完整状态快照，在计数更新的同一同步边界发布。`core/status.py` 复用该快照组装字段，避免分别读到释放前后的混合状态；不在同步状态组装中等待异步锁，不触发模型加载。

```json
{
  "audioConcurrency": {"configured_total": 8, "active_total": 8, "waiting_total": 3},
  "spkEmoConcurrency": {"configured": 4, "active": 3, "waiting": 2}
}
```

A 活动数为 `active_total - active`，A 等待数为 `waiting_total - waiting`，不再增加重复字段。原有 `localModels`、`vadPool` 和 `resourceDiagnostics` 保持含义；增强音频等待数不同于模型池等待段数。

`core/request_telemetry.py` 为事件新增附加 `admission` 对象，包含 `category`、`outcome`、`reason`、`snapshot`；阶段耗时新增 `audio_wait_ms`。快照同时包含两类容量和共享等待数，在判定或授予时捕获，不在错误返回后拼接不一致的读取值。

`reason` 使用有限集合，例如 `total_full`、`spk_emo_full`、`waiting_full`、`wait_timeout`、`role_disabled`、`emotion_disabled`、`both_disabled`、`cancelled`。`outcome` 区分准入、拒绝、超时、取消；等待阶段取消记为准入取消，准入后的失败或取消保留已准入结果，另外通过请求最终 `status` 表达，不能改写成拒绝。汇总增加 `admission.by_class` 与 `admission.rejections_by_reason`，从现有有界事件窗口计算，注明 `window=retained_events`，不会额外保留每个历史请求。

路由在入口初始化该请求的阶段状态，所有提前返回使用本请求的零值或实际耗时；取消标记为取消，避免当前 `response=None` 被误记为完成。保留现有 `[V2阶段]` 耗时字段，分类准入日志使用新增字段，避免破坏已有诊断解析器。日志不增加音频、转写内容或模型对象。

### 7. 以确定性并发和路由隔离测试验收

在现有队列测试中使用 `asyncio.Event`、可控 Future 和受控时钟同步到达、授予、取消和截止，不依赖真实处理速度或长时间 sleep。覆盖 8/4 配置下各类混合状态、错误优先级、原子授予、共享等待上限、同类 FIFO、A 绕过受阻 B、较早 B 可处理后优先，以及全部名额最终归零。

路由测试覆盖三个增强布尔值的组合与功能开关矩阵；能力拒绝时断言准入、音频准备、VAD、Qwen、模型加载及推理均未调用。保留启用模型后的段级失败 `null` 回退、模型无健康副本 `4015/4016` 和 Qwen 段级信号量回归。用可阻塞的假线程验证取消不能在后台推理结束前释放名额。

配置测试使用临时 TOML，状态及模型测试显式构造开关和设备数组，不依赖工作区当前配置。已有针对本地特定 VAD 数量或功能开关的断言必须区分测试前置条件与本次回归，不通过改动实际部署配置消除失败。

## Risks / Trade-offs

- [旧配置升级后 B 默认最多 4 个] → 在提案中标记兼容性变化，部署前显式设置所需新上限，并在状态接口核对。
- [配置关闭由 `null` 成功变为请求失败] → 更新错误码表、调用示例及功能开关矩阵，提醒调用方只请求已启用能力。
- [授予与取消竞争导致泄漏或重复释放] → 租约保存不可变分类和身份，状态转换受同一锁保护，增加精确控制竞争顺序的测试。
- [协程取消后线程仍在执行] → 追踪并等待该请求已启动的不可中断工作收尾，再释放租约；取消完成可能相应延迟。
- [A 绕过 B 增加调度复杂度] → 只比较两类队首的可处理候选，维持全局序号并测试较早 B 恢复资格后的优先权。
- [多实例的容量被误当成全局上限] → 状态与部署说明明确进程内语义；本 change 不新增分布式协调依赖。
- [新增遥测污染早退请求的耗时或无限增长] → 请求入口重置阶段上下文，沿用固定历史上限，使用有限原因键，保持诊断字段兼容。

## Migration Plan

1. 实现并运行定向隔离测试，更新本地和容器配置模板及 README/部署说明；本轮规划不执行这些实现步骤。
2. 部署时核对 `[features]` 与客户端增强参数，明确填写新增 B 上限；未填写时采用 4。原 `audio_concurrency` 保持总容量含义。
3. 重启对应 SeaCraftASR 实例，检查就绪前配置校验及 `/get_status` 两组容量，使用受控 A/B 请求核对 `4013/4017` 与能力错误。无需为此重启独立 Qwen 服务。
4. 回滚时恢复旧代码及配置备份并重启服务；旧版不会执行 B 独立限制，也恢复其原有功能开关行为，调用方需同步知晓行为差异。
