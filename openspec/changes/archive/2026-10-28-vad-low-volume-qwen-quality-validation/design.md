# Design

## Context

当前 `/v2/seacraft_asr` 在 VAD 输出后按段并行请求 Qwen；低音量过滤在裁剪和 Qwen 请求前执行，配置为关闭时不改变原链路。复读保护已经在 ITN 前对单段原始 Qwen 文本执行，并通过日志记录修复或“超长但未识别为复读”的事件。现有压测工具可以统计响应质量，但主要面向顶层音频池，不能直接完成本次目录递归、Paraformer JSON 配对、逐段时间对齐和低音量候选审查。

目标目录实际包含 45 个 WAV 与 45 个同目录 `seaco_paraformer-*.json`，其中前缀使用下划线。Paraformer JSON 是历史系统输出，不能作为人工真值；它只能提供时间、文本和上下文对照。测试报告必须把“相对基线差异”和“人工复核结论”分开记录。

## Goals / Non-Goals

**Goals:**

- 在临时配置下完成 45 个 WAV 的 16 路并发端到端测试，得到可复现的 P50/P95 和逐文件性能数据。
- 从基线独有段中筛选可能被 `-41 dBFS` 过滤的细小声音，并用 RMS、时长、时间重叠和相邻文本提供证据。
- 对最终响应和服务日志执行复读后处理审计，明确哪些复读已修复、哪些被保留、哪些可能漏网。
- 产出机器可读数据、人工复核清单和中文汇总报告，为是否启用 `-41` 及是否单独创建复读优化 change 提供依据。

**Non-Goals:**

- 不把 Paraformer JSON 当作绝对转写真值，不计算未经人工标注支持的 WER 或绝对准确率。
- 不在本 change 中修改 Qwen-ASR 8806 服务，不调整模型解码参数，不修改默认生产阈值。
- 不因发现单个可疑文本就直接修改复读规则；稳定模式需要单独的后处理优化 change 和回归集。
- 不把 VAD 段数减少直接等同于无关内容被正确过滤。

## Decisions

### 决策 1：使用临时配置并固定请求参数

测试生成独立 TOML，覆盖：

```toml
[qwen_asr]
vad_low_volume_rms_dbfs_thres = -41.0
vad_low_volume_filter_enabled = true
segment_concurrency = 4
audio_concurrency = 16

# 请求体固定为
showSpk = false
showEmotion = false
```

服务监听 8084，Qwen `base_url` 仍指向 8806；测试启动前记录 `/get_status`，结束后只关闭 8084 并验证 8806 可用。默认 `config.toml`、原始 WAV、Paraformer JSON 和 Qwen 服务不被改写或停止。

选择 16 路而不是分档压测，是为了严格回答本次目标负载下的端到端 P50/P95；所有 45 个文件分成 16、16、13 三个自然批次，但分位数按 45 个请求汇总。

### 决策 2：先做配对完整性检查，再发送请求

对每个 `seaco_paraformer-*.json` 去除前缀并添加 `.wav`，要求 WAV 与 JSON 位于同一目录。先输出 45 对清单和 SHA256/文件大小；任何缺失、重复或无法解析的配对在压测前失败，避免把错配结果误当作质量差异。响应文件名使用稳定哈希或相对路径映射，避免中文文件名和同名 `教师1.wav` 覆盖。

### 决策 3：用时间重叠建立可解释的基线对齐

解析两侧 `segments[].bg/ed/segment_text`，对每个 Paraformer 段计算与 Qwen 段的重叠秒数、基线覆盖率和 Qwen 覆盖率：

- 有重叠且覆盖率足够的段记为“重叠段”，拼接其文本做相似性诊断；
- 完全没有 Qwen 重叠的基线段记为“基线独有候选”；
- Qwen 段覆盖多个基线段时记为“合并/边界差异”，不能直接判为漏识别；
- Qwen 独有段单独统计，检查是否来自基线切分差异或新增幻觉。

候选上下文取前后各一个有文本基线段和同时间窗口的 Qwen 文本，窗口边界允许小幅时间误差。文本相似度只用于排序和聚类，不作为自动准确率结论。

### 决策 4：把“细小声音无关内容”分成自动证据和人工结论

候选自动记录：WAV 相对路径、时间范围、Paraformer 文本、Qwen 是否有重叠文本、RMS dBFS、峰值、时长、前后上下文和过滤日志证据。人工复核按以下互斥类别标记：

1. `irrelevant_small_sound`：独立短促声音、口气、噪声或无上下文意义，过滤可接受；
2. `valid_lecture_content`：授课、问答、英文或短词，即使音量低也应保留；
3. `boundary_or_merge_difference`：Qwen 有覆盖文本，只是时间边界、合并或切分不同；
4. `uncertain`：仅凭文本和音量无法判断，需要听音频。

只有第一类计入“无关内容被去除”；第二类计入潜在漏识别，第三类不计入过滤成功或失败，第四类单独报告。

### 决策 5：复读审计同时看最终响应和日志

质量扫描复用现有复读指标，并补充：段内最长重复单元、字符连续重复、相邻段完全重复、跨段 12 字 shingle、字符/秒异常、超长段和特殊 token。日志从测试开始前截取到结束后，按测试时间窗口解析 `[复读修复]` 与 `[复读检测]`。

为解决 16 路请求日志交错且当前低音量日志只有临时路径的问题，在诊断日志中增加请求 `task_id` 或稳定临时文件标识；该字段只用于日志和机器可读报告，不改变 API 响应。若实现阶段无法补充相关日志，则报告只能给出全量过滤计数，必须明确无法逐文件归因。

复读分类规则：最终仍出现重复结构且无对应修复记录为“疑似漏网”；有修复日志且最终文本正常为“已修复”；长度超限但无重复结构为“保留并告警”；自然叠词且长度正常为“正常重复，不计漏网”。

### 决策 6：后处理优化采用证据触发

若同一漏网模式在至少两个文件或两个请求出现，且人工确认不是正常重复，则报告建立后续优化 change 的输入：模式样本、当前检测为何未命中、建议的结构特征、误伤保护、配置开关和回归指标。若只有孤立样本或无法排除真实口语，则只记录观察项，不扩大规则。

## Risks / Trade-offs

- **基线本身可能错误** → 报告不称其为真值；所有“过滤成功”必须经过人工复核或标为不确定。
- **时间边界变化造成假漏检** → 同时输出重叠秒数和覆盖率，把合并/拆分列为独立类别，并保留上下文窗口。
- **-41 dBFS 误删弱授课内容** → 把低音量但有连贯文本的样本单独列为潜在漏识别，不以总体段数下降作为通过条件。
- **16 路并发导致服务失败或 Qwen 排队** → 记录每个请求的 HTTP、错误码、超时、服务状态和 Qwen 指标；失败请求不进入成功请求的 P50/P95，但单独报告失败率。
- **日志交错导致无法归因** → 使用 task_id/临时文件标识；如果缺失则降低结论粒度并在报告中明确限制。
- **复读检测规则过严造成误报** → 只把长度异常且结构重复作为已修复/漏网候选，正常长度叠词保留原样。

## Migration Plan

1. 先实现配对清单和分析器的 dry-run，确认 45 对文件、字段格式和输出目录。
2. 生成临时配置，启动 8084，预热并确认低音量过滤开关和 `segment_concurrency=4` 已生效。
3. 截取服务日志起点，按 16 路并发发送全部 WAV，保存响应和状态采样；测试完成后关闭 8084，确认 8806 未停止。
4. 运行逐段对齐、RMS 统计、候选分类和复读审计，保存原始 JSON、日志快照和中间结果。
5. 完成人工复核后生成汇总报告；根据漏网判定规则决定是否创建独立后处理优化 change。
6. 若 `-41` 结果不可接受，生产回滚保持 `vad_low_volume_filter_enabled=false`；本 change 不修改默认配置，因此无需代码回滚。

## Open Questions

无。Paraformer JSON 无人工真值这一限制已纳入规格，报告使用相对基线和人工复核分类，不冒充绝对准确率。
