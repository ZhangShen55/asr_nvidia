# Design

## Context

现有lifespan依次启动VAD和预加载Qwen，增强池由请求调用load_v3_models_if_needed触发。ModelPool已有按数组顺序加载、健康/失败状态及关闭逻辑。

## Goals / Non-Goals

目标：将增强池首次加载移至就绪前，继续使用每服务共享池。
边界：只加载权重并建立runner；不执行语音forward暖身，不增加性能验收范围。

## Decisions

1. 在VAD/Qwen现有启动步骤之后、lifespan yield之前调用增强预加载入口；两个能力独立检查features开关和非空设备数组。直接采用新启动行为，不引入可选开关或保留两套启动策略。
2. 复用ModelPool.ensure_loaded，依数组顺序完成全部实例的加载尝试。不开第二套池；请求仍走原能力校验及ensure_loaded，已加载实例直接复用。
3. 保留增强池现有降级契约：部分失败使用健康实例；某池全部失败也继续尝试另一池，服务仍可用，对需要失败能力的请求沿用不可用错误。不能直接让load_v3_models_if_needed的全池失败异常中断启动。意外启动异常或取消则沿现有finally回收已创建资源。
4. 继续使用现有状态字段报告配置/健康/失败，不把完成加载尝试等同于全实例成功。关闭功能或空数组跳过；GET不加载。

## Risks / Trade-offs

- 启动时间变长，未使用增强的A请求部署也会提前占用增强权重内存 → 文档明确此行为；保持现有开关与数组禁用能力。
- 加载不保证首个forward无编译开销 → 不承诺首请求完全暖态或具体提速。

## 验证方法

1. CPU替身生命周期测试：阻塞加载时lifespan不得到达yield；两池加载顺序/实例数正确；关闭功能、空数组跳过；部分/全部加载失败按原规则降级且另一池仍尝试；启动取消/异常关闭部分资源。
2. 请求复用与状态测试：就绪后两次双增强请求不增加模型构造次数；showSpk/showEmotion独立控制调用，纯A不调用增强；GET不增加加载次数。运行现有相关模型池/生命周期/能力回归。
3. 一次真实NPU7冒烟：使用当前Qwen4/CAM4/emo1配置启动独立owned服务；在任何音频请求前保存GET与启动日志，核对CAM健康4、emo健康1及身份。取现有语料中能产生1～10秒有效VAD段的短音频，连续发送两次showSpk=true/showEmotion=true请求，检查两分支真实调用、响应与实例复用。无需四路完整音频矩阵或P50/P95；短片不足以覆盖所有CAM推理槽也不要求轮流暖身。
4. 正常TERM本次服务，核对其父/worker出生身份退出、测试端口持续释放至少5秒，保留既有服务；简要记录实际结果。真实故障立即停止并收尾，不恢复HBM提前停止线。
