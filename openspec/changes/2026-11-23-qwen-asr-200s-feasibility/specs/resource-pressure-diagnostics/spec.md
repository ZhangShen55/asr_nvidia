# Spec Delta

## ADDED Requirements

### Requirement: 可行性实验与正式实现隔离
200秒可行性验证 MUST 冻结源码、配置、依赖、权重及输入身份，在独立副本记录最小实验接线和全部差异。实验 MUST NOT 改写正式业务代码、默认配置、现有服务、旧change任务或历史结果；实验多实例 MUST NOT 被解释为正式continuous多实例能力。

#### Scenario: 实验需要多模型路由
- **WHEN** 当前正式continuous只支持单实例，而候选需要多worker
- **THEN** 仅在隔离副本接线，记录模块实际来源和补丁，不把绕过校验或独立模型脚本当作真实服务支持

### Requirement: 二百秒可行性以完整真实接口为依据
可行性结论 MUST 来自原八完整WAV及其SHA一致的八并发v3请求，执行真实音频加载、VAD、短于0.3秒过滤、裁剪、通信、转写与ITN。测试 MUST 保持独立段完成及安全补位；组件、缓存VAD或预制PCM成绩只能定位问题，MUST NOT 替代真实端到端结果。

#### Scenario: 原八完整音频验收
- **WHEN** 候选进行有效性验证
- **THEN** 保留八源身份、请求字段、响应、各请求时间与全轮墙钟，确认每条最多16段、全局最多128段，而非预切段一次性全部送入

### Requirement: 同卡候选保持可比并受控扩展
实验 MUST 固定物理NPU7、原权重/精度、生成参数、过滤与复读策略、增强开关、总CPU预算和全局缓冲约束，分别验证多模型分担及供给隔离。模型数升档 MUST 有上一档的真实HTTP收益、安全余量及关闭证据；MUST NOT 将多卡收益或增加总段窗口当作多进程收益。

#### Scenario: 单因素比较
- **WHEN** 比较单worker与双worker
- **THEN** 八音频每条16/global128保持一致，明确各worker绑定、预算与共享占用；不能同时打开供给隔离后把全部收益归于模型数

#### Scenario: 不满足扩展条件
- **WHEN** 当前候选收益不足、HBM余量不足或收尾失败
- **THEN** 保存原因并停止该分支升档，不为覆盖矩阵强行运行四/八worker

### Requirement: 二百秒目标及三百三十六秒停止闸门
本轮 MUST 以八请求提交至全部响应接收的墙钟≤200秒为保守目标线；200至336秒为未达目标，MUST NOT 自行放宽容差。稳定阶段连续窗口的偏乐观预计仍≥336秒时 MUST 提前停止；336秒尚未全部完成 MUST 硬停止。提前停止 MUST 保存预测输入、假设、可信度及实际进度，MUST NOT 宣称已证明硬件绝不可能达到200秒。

#### Scenario: 连续窗口收益不足
- **WHEN** 全八VAD进度已知、稳定窗口充足且按预定规则生成的连续偏乐观预计仍≥336秒
- **THEN** 停止追加和本轮处理，进入有界收尾并及时报告；不能等待至旧420秒闸门或原样重跑

#### Scenario: 预测证据不足
- **WHEN** 启动期、进度缺失、共享负载突变或尾部加速无法合理估计
- **THEN** 标记预测不可信，不用单个批次或全局平均段速定论；最迟在336秒未完成时停止

### Requirement: 分阶段归因与缓存指标含义明确
诊断 MUST 区分段窗口等待、裁剪排队/计算、提交锁/通信、待prefill、输入准备、prefill、KV布局整理、decode及同步收尾。并行段累计时间与共享模型步墙钟 MUST 分列；指标不可观测时须标未知。缓存布局直接沿用率 MUST NOT 被解释为跨VAD内容复用率或只有少数token使用KV。

#### Scenario: 某段驻留时间较长
- **WHEN** 段调用驻留时间明显大于模型计算时间
- **THEN** 用阶段证据区分正常共享等待、供给阻塞及执行开销，不把所有驻留时间归为纯NPU计算

### Requirement: 速度结论同时保留输出质量证据
每轮 MUST 分列处理完成、严格无警告成功、非空文本、段警告、fatal及未完成删失。完整配对输出 MUST 展示具体边界、文本、语种、复读与截断差异；缺配对须标未知。MUST NOT 通过减少有效段、缩短生成上限或静默丢弃异常换取提速，MUST NOT 把模型输出当人工真值。

#### Scenario: 候选完成但参考不完整
- **WHEN** 候选8/8返回而基线因停止闸门仅返回部分音频
- **THEN** 已配对部分逐段比较，其余使用已有同源参考及定向听音复核并标注来源；质量证据不足则只能报告性能结果，不能声称整体可行

### Requirement: 删失统计及复验结论可审计
未完成轮 MUST 标记停止原因、各请求状态、完成子集分位数及样本数，MUST NOT 给出完整八请求P50/P95或精确整轮提速比。支持后续改造的积极结论 MUST 有同一冻结候选三轮真实HTTP复验均8/8在200秒内完成、输出质量复核与正常资源关闭证据；不足时须降级结论。

#### Scenario: 基线或候选被提前停止
- **WHEN** 任一比较轮存在未完成请求
- **THEN** 完整耗时及精确速度比标未知，实际删失与预测分开；只给有证据支持的界限和完成数，不能用预计耗时充当实测

### Requirement: 可行性验证允许负结论并完整回收
验证 MUST 输出目标可行、局部改善未达目标、该候选收益不足或证据不足/实验无效的有界结论。每次结束、失败和提前停止 MUST 回收登记的自有服务/worker、核对出生身份、端口空闲至少5秒及私有缓存，保留共享服务与日志。负结论在证据及收尾齐备时属于验证交付完成，MUST NOT 自动触发正式改造、推广或旧change归档。

#### Scenario: 候选没有足够收益
- **WHEN** 真实场景触发收益不足停止且取证与回收完成
- **THEN** 交付该候选不值得继续的原因，条件性扩展任务记录未触发；不能伪造性能通过或继续扩大实施范围
