# Design

## Context

动机见proposal。权威代码在`xjtu910b7:/home/zhangs/asr_nvidia`，冻结起点`a1de07fb8cff9018d0b9082645b954e2fcc919be`，conda asr、原HF/BF16、物理NPU7。正式根配置仍legacy48/384；本实验基线来自`test/config.qwen-continuous128.toml`（A8、16/128、prefill16、3ms交接、保护开启）。正式continuous在Settings校验和client路由中均限单worker。

历史独立128段4.43秒静态/7.62秒连续来自时长分层样本，不是八完整音频自然供给。最终真实HTTP仅2/8完成，worker快照prefill217.31秒/decode150.19秒，均非纯算子时间；裁剪实际工作少、调度等待大和KV布局整理多是待证假设。早期CPU回归意外预加载曾污染观察轮，因此本轮CPU与NPU验证必须严格隔离。

## Goals / Non-Goals

**Goals:** 在真实完整链路下判断200秒目标是否值得后续投入；区分同卡模型并行与供给隔离的收益；达到收益不足条件及时停止，允许负结论交付。

**Non-Goals:** 正式多实例支持、业务重构、KV存储方案重做、部署推广、依赖升级、换引擎/精度/权重、扩大段窗口、改变VAD或结果策略。独立实验代码及补丁只是验证资产，不合入正式业务路径。本轮提案阶段不启动服务或模型。

## Decisions

### 1. 独立副本的真实服务，而非模型脚本替身

apply时创建独立临时checkout/副本，不覆盖权威工作区。记录基线与全部补丁SHA、实际模块路径、解释器/依赖/权重元数据及输入SHA。权重与测试音频只读引用，配置/统计/PCM缓存/端口各自独立，不复制整个模型。权威目录仅增加本change及其实验说明/报告资产；实验副本接线不得自动回流业务源码。

多模型在同一个真实v3服务实例内接入独立Qwen worker，保留原八CPU VAD与ITN路径；不能起八套完整ASR服务、重复扩大VAD/HTTP准入，再宣称只改变模型进程数。临时放宽校验必须同时实现正确路由、逐段归属、取消与所有worker关闭，单纯修改实例数不是有效候选。

### 2. 矩阵和分支闸门

|轮次|模型数|每worker固定负责音频数|每音频在途|全局在途|供给方式|
|---|---:|---:|---:|---:|---|
|B0|1|8|16|128|当前基线|
|M2|2|4|16|128|与B0相同|
|S1|1|8|16|128|仅隔离裁剪/发送供给|
|M4（有条件）|4|2|16|128|仅模型数变化|
|M8（有条件）|8|1|16|128|仅模型数变化|
|MS（有条件）|已证有效档|固定映射|16|128|组合两个已证有效因素|

按输入manifest顺序固定音频到worker映射，同一音频所有段留在同一worker，不迁移正在生成的KV。每个模型仍是单设备执行owner，不同模型竞争同一张卡的重叠能力必须实测。候选按B0→M2→S1顺序，M2失败只关闭模型数分支，S1可独立验证；资源红色闸门/收尾失败则整批停止。M4/M8/组合必须有前档真实HTTP改善、200秒差距具备解释、显存余量及正常关闭证据，不能为凑矩阵全跑。

八完整请求并发恒为8，每音频16/global128恒定，prefill上限16及单实例实际计算上限明确记录。每worker帧/token预留、全局PCM与CPU亲和/线程总预算在运行前冻结；禁止将同一个全局预算复制N份后混淆变量。无法等价分配的项目必须列为额外变量，不作单因素因果结论。只测A纯转写，沿用三项增强false；无B模式或其它卡的可行承诺。

S1只允许独立有界裁剪执行器和每worker专用有界发送队列的最小接线，控制消息保留容量、已接收未知不重发，Future终态及取消安全回收不变。暂不修改KV算法或prefill/decode策略；若定位到这些问题，仅交付归因和后续方向。

### 3. 相同真实输入与时间边界

原八源manifest取自`/tmp/asr-a8-http-20261119-manifest.json`并逐文件重新验证，不假定临时文件仍存在；缺失时按旧run中的八源SHA恢复映射。每轮真实请求走正常音频加载/VAD/0.3秒过滤/裁剪/IPC/Qwen/ITN，不能用缓存VAD或已裁剪PCM替换正式计时链路。组件回放只能另存为诊断证据。

固定原HF、BF16、greedy、max_new_tokens256、原复读阈值/恢复策略及过滤开关，保留时间轴、语种与响应契约。记录每请求起止、所有HTTP上传/响应完成；主指标T_batch从八请求共同启动闸门释放到最后一个完整响应接收，另列各请求耗时。服务启动/权重预加载、短clip暖身、正式请求、收尾分别计时。首次冷态结果另列，不能混入暖态三轮。共享负载在各轮前后及期间采样，明显漂移标为受干扰，不能以相隔数天的旧轮充当同时期配对。

### 4. 200秒目标、可信提前停止和硬截止

用户表述“约200秒”，本计划采用≤200秒作为保守积极结论线，不自行放宽；200<T<336只报告局部改善及差距。约336秒来自历史420秒改善20%，不是新的成功目标。T_batch达到336秒且未8/8完成时必须停止；不再等420秒。

预测器候选规则：全八VAD段数已知、正式t≥90秒、至少60秒连续有效进度后，每30秒评估一次。按各音频独立完成进度计算剩余工作，使用最近30/60秒及此前最快可比窗口的较快吞吐，并额外保留25%加速余量，形成偏乐观ETA；同时评估其它音频结束后释放算力、段长/token分布和ITN余量。至少连续两次可信ETA≥336秒才提前停止。单个批次耗时或全局平均段速不构成可信预测。

这套ETA是经验估计而非数学下界。若进度不可观测、样本难度变化、长尾释放/共享负载可能带来未建模加速，必须标为不可信，不提前断言不可行；硬336秒仍有效。CPU合成轨迹覆盖加速、减速、短抖动、缺失、音频逐个结束与阈值边界，并用既有真实进度回放校验后才在本轮启用。预测规则及版本必须在首轮前冻结，不能看完候选结果后改规则选择性停止。

触发后立刻停止追加、保存轻量最后快照、取消owned请求并有界收尾，记录触发时间和关闭时间；及时报告原因，不以重试/升档继续同一失败方向。若证据仅支持“该候选本轮收益不足”，不能扩写成“910B硬件绝对不能200秒”。

### 5. 诊断与质量

用单调时钟区分：窗口等待、裁剪排队/计算、提交锁/队列、IPC发送/接收、待prefill、输入准备/搬运、prefill forward、KV布局整理、decode forward、必要同步/结果回读、完成到补位。共享物理步只计一次，段累计驻留与墙钟分开；无法拆出的内部阶段标未知，不将整个prefill/decode包络称为纯NPU计算。优先使用实验接线中的计时，诊断开销需做轻量对照，不为取证逐段增加全设备同步。

记录生成token与时长分布、实际物理步大小、逻辑在途、帧/token/PCM约束、重排次数及布局直接复用次数。不同段不共享内容KV；同段解码继续使用其KV，49/951这类布局计数不是KV内容命中率。在线摘要有界且不含正文；授权实验结果可保存完整文本及原段归属。

完成率、严格无警告率、非空文本、生成异常、fatal、取消/删失分别计数。输出具体逐段差异（文本/时间/语种/警告），不把缺参考当零差异。基线未完整时，可引用已有同源完整结果作质量参考、定向听音；参考是模型输出而非人工真值。明显漏字、错语种、异常重复和截断须复核，证据不足就报告未知，不得支持正式改造。

### 6. 复验、负结果与资源归属

先做每候选一轮真实HTTP筛选，负结果不原样重复；只对有望接近目标的冻结候选追加至三轮有效正式复验。三轮均8/8且T_batch≤200秒、无已确认新增质量问题/未决显著差异、正常资源关闭，才给出“目标可行”的积极建议。完整轮分位数为n=8，三轮分别报告；若合并n=24须明确非独立来源，不将重复音频当24独立样本。

只要矩阵决策、证据、停止原因与正常清理齐备，负结论也可完成本验证change。因条件未触发而跳过的M4/M8/组合/复验必须写decision log，不能标为跑过；质量/资源问题不能被“负结果可交付”掩盖。不会自动实施任何后续业务改造，也不替旧change完成或归档。

所有轮次串行使用NPU7；CPU回归须Python导入前设置r4设备/权重guard、独立TMPDIR/stats/cache，不与正式NPU轮并行。记录owned父子PID/出生时间/端口/日志，CANN环境正确继承。HBM可用不足8GiB、持续换页/主机安全水位不足、OOM或owned健康异常触发资源红色闸门；新档预估峰值无法保留8GiB余量则跳过，预估不是加载成功证明。阈值与起始资源快照一起冻结，保留既有服务。

收尾优先正常关闭，整体有界等待与失败升级规则在启动前登记，仅对再次核实归属的PID处理；强制回收单列失败，不能算正常shutdown。验证进程出生身份消失、端口连续5秒空闲、私有PCM缓存空、共享服务仍在，日志/旧stage不删除。候选代码、配置、模块来源与补丁保留，实验服务全部释放，权威工作区最终干净。

## Risks / Trade-offs

- 同卡多个副本争抢算力及重复占用HBM → 分档、真实接口单因素比较；显存不足允许不测更高档。
- 多进程只让单段更快但总吞吐下降 → 以八请求整体墙钟/完成数优先，段P95只是辅助。
- ETA误判、启动或尾部扰动 → 连续可信窗口、偏乐观余量和真实轨迹回放；证据不足只启用336硬闸门。
- 测量开销影响执行/共享服务变化 → 有界低频观测、记录开销及竞争，受干扰轮不归因。
- 缺少完整人工真值 → 展示实际差异与未知，性能可行和整体质量可行分开；不编造召回率。

## Migration Plan

本轮无部署迁移。先创建独立验证副本与证据清单，完成小规模正确性/关闭检查，再按矩阵执行真实HTTP并及时停止失败分支；结束仅提交验证资产和报告、释放副本中的服务，不合并实验业务补丁。后续正式改造需要用户另行发起change。

旧continuous change保持20/25；旧throughput change保持原任务状态。当前差量只向诊断规格增加带实验范围的要求，不改变服务单实例/默认值；准备同步任何规格前都检查两个旧差量与本差量的合并预览和顺序，不顺带勾选旧验收。
