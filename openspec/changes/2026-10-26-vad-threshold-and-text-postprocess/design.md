# Design

## Context

现有 VAD 由 `core/vad_pool.py` 的 worker 进程承载，worker 构造参数目前只包含单段最长时长和结束静音时长。FunASR FSMN-VAD 的 `speech_noise_thres` 在模型选项初始化时写入检测状态，因此仅在一次 `generate` 调用中临时增加字段不能保证阈值真正改变。

现有转写链路在 Qwen 分段结果上先计算 `language_ratio` 和 `speed_info`，再执行 ITN 与标点清理。`sanitize_segments` 删除分段后，统计字段可能保留已删除分段的影响。当前顶层 `language` 取第一个有语言信息的分段，不能表示中英比例最高的最终语言。

参考音频的人工结果不是严格 JSON：标注行使用裸文本 `细小声音`，另有人工说明文字和少量缺失逗号。测试必须把它当作人工标注文档解析，不能把该文件直接作为标准 JSON fixture。

## Goals / Non-Goals

**Goals:**

- 让 VAD 语音噪声阈值成为真正作用于所有 worker 的配置项，并提供可重复的阈值对比出口。
- 让本地模型设备配置使用可读且可校验的 `cuda:N` 形式，同时保持 VAD 独立设备边界。
- 让语言判定、英文口气词替换、单字语气词移除和最终响应统计使用同一组有效分段。
- 让既有部署配置具备一次迁移所需的兼容提示，并让标准配置只保留新结构。

**Non-Goals:**

- 不修改 Qwen-ASR 模型或 Qwen 服务容器的推理参数。
- 不对音频做自动增益、降噪或重采样来替代 VAD 阈值调节。
- 不把所有中文语气词做语义级改写；本次只处理规格中列出的四个单字词和英文边界替换。
- 不把 55 分钟参考音频的长时测试加入默认快速单元测试集合，也不在本次 change 中构建镜像或部署服务。

## Decisions

### 1. VAD 阈值使用 `vad_speech_noise_thres`

在 `[qwen_asr]` 中增加 `vad_speech_noise_thres = 0.6`，配置属性映射为 FunASR 的 `speech_noise_thres`。`VadPool` 创建每个 worker 时把该值放入模型构造的 `vad_kwargs`；worker 预热和每次推理复用同一份值。配置读取阶段校验数值范围 `0.0 <= value <= 1.0`，非法值在服务启动时明确报错。

选择该命名而不是泛化的 `vad_sensitivity`，是为了让配置名称与 FunASR 的实际判定参数对应，避免“灵敏度越大越灵敏”的自然语言误解。文档提供三个起始档位说明：`0.3` 偏灵敏、`0.6` 正常、`0.8` 偏不灵敏；最终推荐值由参考音频测试报告决定，默认不因单个样本直接改变。

### 2. 参考音频采用区间标注回归，不把响度当唯一判据

测试解析每个分段的 `bg`、`ed` 和 `segment_text`，读取对象开始到 `segment_text` 前的标注行；包含 `细小声音` 的对象归入负向标注。额外说明文字只作为注释跳过。人工结果中预期得到 46 个标注段，测试启动时断言数量，防止标注格式变化后静默失效。

每个阈值档位记录：

- 标注段抑制率：标注区间内没有 VAD 输出达到最小重叠比例的占比；
- 非标注回归保留率：与默认阈值基线相比，未标注区间的有效 VAD 段保留情况；
- 过滤后段数、发送给 Qwen 的段请求数和端到端耗时；
- 标注段与非标注段的 RMS/峰值分布，仅用于解释结果，不作为单独通过条件。

标注段判定使用时间重叠比例而不是文本内容：VAD 输出与标注区间的重叠时长除以标注区间时长达到 50% 即视为检测到。这样可以容忍边界轻微漂移，同时能把“检测到但边界不同”纳入误检统计。

### 3. 设备串在配置边界归一化

`[model_device].emotion2vec` 和 `[model_device].speech_campplus` 的标准值为 `cuda:N` 字符串。模型加载前统一解析为规范设备对象并校验 CUDA 可用性及设备编号；状态接口继续返回规范字符串。

为降低已有部署的升级风险，读取层可暂时接受旧整数索引并转换为 `cuda:N`，同时记录迁移警告；标准 `config.toml` 和 `config.docker.toml` 只写字符串。`[qwen_asr].vad_device` 仍独立支持 `cpu` 与 `cuda:N`，不再新增或恢复 `[model_device].vad`。

### 4. 日志路径使用嵌套配置并提供一次性兼容读取

标准配置使用 `[log].log_path`。`Settings.log_path` 优先读取嵌套键；为已有部署提供顶层 `log_path` 的短期回退并记录 warning。两份标准配置删除顶层键，配置结构测试断言新位置存在且旧位置不存在。后续可在兼容周期结束后移除回退逻辑，避免无效配置长期保留。

### 5. 统一后处理流水线

内部处理顺序固定为：

1. 解析 Qwen 文本并执行现有复读修复；
2. 对原始分段文本去除外围空白和标点，精确删除仅含一个「啊」「哦」「嗯」「呃」的分段；
3. 对剩余分段按 Qwen 返回的语种和文本字符数计算占比，最高占比决定顶层语言；相同占比取时间顺序最早的语种；
4. 最终语言为英文时，使用边界/空白/标点限定的替换规则，将四个中文口气词映射为 `ah`、`oh`、`um`、`uh`；
5. 构造响应分段，执行 ITN 和标点卫生清理；
6. 使用清理后的最终分段重新计算单句速度、`speed_info` 和 `text`，并使用“未被删除分段的原始 Qwen 语种文本”计算 `language_ratio`。

`language_ratio` 保持现有“模型语种标签 + 文本字符数”的统计口径，不把中文 `嗯` 替换成英文 `um` 后重新归类；但所有被删除的分段都必须在统计前排除。内部结果保留稳定的分段索引，使 ITN 或标点清理删除分段后可以同步更新统计，而不会依赖最终数组位置。

删除单字语气词发生在说话人聚类之前，避免无效短段参与角色聚类。英文替换只改变展示文本，不改变 `bg`/`ed` 和模型语种标签；速度值在最终文本确定后重新计算。

### 6. 测试分层

- 配置单元测试：日志路径嵌套读取、旧配置回退、VAD 阈值默认/边界、`cuda:N` 解析和非法设备。
- 文本纯函数测试：单字语气词（含外围标点）删除、包含有效文本时保留、英文映射边界、中文和混合语言不误替换。
- 管线测试：验证删除后 `segments`、`text`、`language_ratio`、`speed_info` 一致，角色/情绪字段不被错误重排。
- 参考音频集成测试：默认标记为显式长测命令，比较 `0.3/0.6/0.8` 三档并输出 JSON/文本报告；不要求每次普通单测运行 55 分钟音频。

## Risks / Trade-offs

- **阈值提高后漏掉真实小声语音** → 默认保留 `0.6`，先用 46 个标注段与未标注回归保留率做对比，报告同时记录漏检变化，不用段数下降作为唯一指标。
- **响度受说话距离、麦克风和背景噪声影响** → RMS 只作为诊断指标，最终以人工区间和 VAD 输出重叠统计为准。
- **英文主导的混合音频中存在真实中文内容** → 只替换边界明确的四个口气词，并要求英文为最高占比语种；不做任意中文字符替换。
- **ITN/标点清理再次删除分段造成统计错位** → 用稳定内部索引保留分段与语种统计关联，所有最终统计放到清理完成后生成。
- **旧部署仍使用顶层日志路径或整数 GPU 索引** → 新结构优先、旧结构短期回退并告警；标准配置和文档只发布新格式。
- **长音频集成测试耗时和依赖较重** → 将其作为显式集成测试入口，普通单元测试使用短文本和打桩 VAD/Qwen 数据覆盖逻辑。

## Migration Plan

1. 先发布代码和标准配置读取兼容逻辑，标准配置切换到 `[log].log_path` 与 `cuda:N`。
2. 重启服务后检查 `/get_status` 中模型设备、VAD 设备和 worker 状态，并运行短音频 smoke test。
3. 在目标机器执行参考音频三档阈值测试，依据报告选择部署阈值；若有效语音漏检不可接受，将阈值回退到上一档并保留后处理规则。
4. 观察日志中的旧配置迁移 warning；确认所有部署改为新格式后，再在后续变更中移除旧键回退。
5. 回滚时恢复旧配置键和值，并回退对应版本；文本后处理的开关或映射若需紧急撤回，应保留原始分段日志用于复核。
