# Design

## Context

动机见 proposal.md。当前 core/qwen_asr_runtime.py 使用一次 generate() 后 batch_decode；上游逻辑future不能改变其物理完成屏障。独立128段HF稳态约4.60秒与旧服务满批约10秒、个别41秒并不等价，历史根因尚未闭环。官方utils的重复折叠及当前utils/repetition.py均为生成后修复，不能节省已消耗decode。

远程源码为权威，固定conda asr、原HF权重BF16和物理npu:7，保留既有服务；实验在独立输出目录，不升级现用依赖。原VAD每音频一个worker、最短0.3秒、独立前端/语言、CAM/emo与ITN行为保持。

## Goals / Non-Goals

**Goals:** 实现模型执行中独立完成和新段进入；16/128真实有界；复读长尾治理；可复算质量和真实8并发验收。

**Non-Goals:** 不保证128恒满、零开销或420秒必过；不借更低生成上限、过滤更多有效语音换取速度；不引入第二套引擎、额外Qwen副本或新增对外路由/错误码。

## Decisions

### 1. 单owner分步执行，先做可验证原型

保持一个spawn Qwen模型worker、一份权重和一个设备执行owner；将模型forward包装为音频前端/多模态prefill/文本decode adapter，复用原参数、位置和精度规则。禁止多个线程同时generate。worker接收段级SUBMIT/CANCEL并异步发送每段RESULT，状态查询只读缓存；RPC以request_id、segment_id、attempt_id和worker出生身份关联，不能仍等待整个RPC批完成。

采用动态活跃集合与独立KV块：初版在每步构造经过验证的左padding KV视图及有效mask、cache_position/position_ids；推进后将有效新KV归还每段持有块，完成段于安全步边界退出。无需首版引入PagedAttention。所有KV留NPU，不逐步整份搬回CPU；容量按实际长度/预留上限约束。动态packing成本必须测量，若此布局过慢则在同一adapter内改为预分配槽位，仍须满足连续接纳契约；不能退回静态generate后声称完成。

先关闭新复读保护，验证原HF与分步adapter的teacher-forced logits、greedy token、位置与音频有效特征；BF16导致差异须逐段展示并复核，数值差异不直接称准确率变化。小规模不能正确持续接纳则停止升压并保留失败。

### 2. 窗口、供给和公平性

段状态为 PENDING→ADMITTED→PREPARING→READY→PREFILL/DECODING→FINISHING→终态。每音频16/global128的逻辑credit覆盖ADMITTED至安全完成FINISHING，原始段描述等待不占；准备缓存另受字节/段数预算约束。max_inference_batch_size仍为单步实际计算成员上限，目标128，不等于实际占用。KV容量不足内部反压，不虚报128真实活跃。

音频使用轮转公平选取，不把首文件所有段切成PCM；每音频有限消费者，在段credit归还后取下一段，提前准备只在有界预算内进行。owner在每个decode步后处理完成、取消和新ready；有ready/槽位时下个周期发起prefill，不再等100ms凑整批。prefill按可用预算分块并与decode交替，确保两者均不饥饿；记录每步耗时与最大等待。尾部一音频仍最多16，不能自动借用其它音频额度。

### 3. 完成与资源契约

EOS只结束所属序列。先确认相关设备操作/结果读取完成，发RESULT、清理KV并完成幂等credit归还，再调度新段；其它序列可继续持有KV。不要求每步全设备同步，使用经验证的执行流/事件边界，不能提前复用内存。取消在安全边界处置，重复取消只清理一次；worker死亡确认前不伪称资源可用。增强汇合预算独立，不能等CAM/emo返回才还Qwen槽位，原始段最终按VAD序号汇合。

### 4. 复读判据与异常策略

提取纯正文的增量尾窗检测组件，状态按段隔离；字符/短语循环、持续次数、异常长度/时长共同判定，设置最少观察量及可配置开关。初始阈值先离线标定保护集，再固定候选profile；不直接照搬官方20次后处理阈值为在线停止规则，不全局no_repeat_ngram硬禁正常重复。

正常EOS与repetition_stop、length_limit、timeout、cancelled、error分别记录。本轮保守策略：复读或非EOS长度耗尽均按段推理失败映射原4012，不将不完整文字当完整成功，也不自动原样重试；完整音频沿用既有失败传播，记录首个异常段及其余段的取消；连带取消不计作额外推理故障，部分文本不算完整成功。测试报告另列可用部分文本、修复差异和被停止原因。既有正常返回的生成后修复继续在ITN前；更宽松的部分成功响应不在本轮引入。

### 5. 容量重试

正常路径由窗口/内部背压避免拒绝。明确未接收的capacity_rejected才启动0.1/0.5/1秒有界退避，首次拒绝后30秒内最多3次重试；30秒是接纳重试窗口，与推理timeout/420秒闸门分开。稳定段ID的已接收/完成表去重，有界保留到父请求排空；通信状态未知不盲目重发。其它执行异常不套用这套容量重试。

### 6. 配置、可观测性与回退

增加经类型/范围校验的连续生成模式与在线复读候选配置（准确字段在实现时随README固定），保留legacy静态执行作为对照/回退，但候选失败不静默降级。测试profile明确audio8、segment16、request128、单步上限128及PCM/KV预算；本提案不改根384配置，推广需性能与质量通过。

记录单调时钟：排队、CPU准备、prefill/decode、结束、EOS→可复用→调度→新prefill/首token。物理步包络只计一次，共享步不能给每段求和冒充全设备耗时。在线有界摘要不存正文；具体原始文本/token差异仅存本轮授权测试目录。原gpu_time_ms和响应类型不变。

### 7. 多Agent分工与集成顺序

| 负责人 | 独立写入范围 | 交付与依赖 |
| --- | --- | --- |
| Agent A | runtime/process及新增KV/forward adapter、对应测试 | 原生分步正确性、段级RPC、真实持续接纳 |
| Agent B | queue/scheduler/client/segment_pipeline及对应测试 | 公平16/128窗口、供给、取消和幂等容量重试；对接A接口 |
| Agent C | 独立增量重复组件、repetition单测、质量报告工具 | 纯CPU检测接口与保护集，A负责模型循环接入 |
| 主Agent | config、API汇合、状态/遥测、文档/集成与实机测试 | 固定接口和资源归属、审阅证据、统一NPU执行 |

先由主Agent冻结SegmentRequest/Result、事件、错误/接收确认、credit/KV所有权，再并行A/B/C；若改同文件，按所有者交接补丁，不同时编辑。子Agent可做CPU或文档工作，无权自行启动NPU服务。仅主Agent串行使用NPU7；各任务独立TMPDIR/日志，端口登记，避免共享测试cache写删。NPU失败先定位小规模，不并行抢卡或原样重跑完整压力。

## Risks / Trade-offs

- 动态KV重排与频繁prefill可能比静态批慢 → 先标定1/16/混合短长/128段、缓存字节和步开销；公平步调度不得变成另一种长prefill屏障。
- BF16形状变化改变greedy路径 → 同源关闭新保护的配对比较，逐条保存差异；关键漏字/错语种需人工听音，不能假设任一路径是真值。
- 复读误杀讲课 → 中英强调、结巴、数字/字母、朗读/歌词保护集；异常按失败透明呈现，不能少生成伪造提速。
- 连续生成改动范围大 → 原型门槛后才接服务；失败保留原因和回退配置，不强行验收。
- 老change仍open并有静态批假设 → 实施前建立需求/任务映射，旧证据原样保留；归档前合并预览检查，避免后归档的旧差量覆盖本契约。

## Migration Plan

1. 记录源码/依赖/权重/输入SHA及旧profile，完成旧任务映射；固定接口、失败策略和测量口径。
2. 并行组件开发，CPU验证，再串行小规模真实NPU原型；验证真实“短段完成→新段执行→旧长段结束”顺序及隔离。
3. 服务候选集成；同源静态/连续、保护关/开对比，排查历史慢批与独立测试差距，完成资源与故障回归。
4. 真实v3八并发16/128验收详见test-plan.md；420秒失败即诊断停止，结论可为目标未通过，不得填完成掩盖。
5. 验收后中文Conventional Commit保存实现和报告；按实际验收决定是否推广候选。回退显式切回旧模式并重启，不能中途改变运行中序列布局。只有所有必需项通过才同步规格、独立归档；旧change不被本轮顺带标为完成。
