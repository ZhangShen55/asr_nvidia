# Spec Delta

## ADDED Requirements

### Requirement: 连续段执行可归因且遥测有界
系统 MUST 按稳定请求/段ID记录准入、准备、prefill、decode、结束、资源可复用和下一段实际执行事件；报告逻辑窗口、真实活跃序列、物理步大小、KV/PCM预算及空槽原因。在线状态 MUST 使用有界摘要且不保存正文，不能为采样阻塞推理或触发加载。

#### Scenario: 验证完成即补位
- **WHEN** 一个段完成且同音频仍有可执行段
- **THEN** 证据显示EOS至资源可用、调度、下一prefill/首token的间隔，区分CPU准备、设备步边界、预算、无供给及调度等待，不将提交时间当作真实执行时间

### Requirement: 同源配对定位服务性能差距
诊断 MUST 用相同真实段、PCM、提示、生成参数、精度和暖态对比静态HF、分步执行及服务路径，分别报告前端、传输、prefill、decode、同步和后处理。MUST 核对共享卡竞争及文本差异，不以输入长短、HTTP开销或冷启动的猜测代替归因。

#### Scenario: 历史慢批重放
- **WHEN** 复现旧服务约10秒以上批与独立128段约4.60秒的差异
- **THEN** 优先重放可恢复的历史同批成员；无法恢复时记录缺失并使用固定新同源配对，不能宣称已证明历史根因；复读保护关闭/开启分别比较

### Requirement: 真实八音频16与128接口验收
调整完成后 MUST 启动真实服务，通过v3接口对原八个不同完整WAV执行八并发，每音频16/全局128、单Qwen物理卡7。MUST 校验源SHA及请求参数，分列冷暖态、A/B增强条件、共享占用，记录每条结果、成功率、P50/P95、总墙钟、420秒内完成数及HBM；固定128段离线实验 MUST NOT 替代此项。

#### Scenario: 八条全部在闸门内完成
- **WHEN** 八条真实HTTP请求均在420秒内正常完成
- **THEN** 报告8/8、各请求耗时及分位数算法、客户端首发至最后完整响应墙钟，核验输出段归属和具体文本差异；复读/长度异常单列，不能靠漏段和截断加速

#### Scenario: 420秒仍有未完成
- **WHEN** 任一请求墙钟达到420秒而未完成
- **THEN** 下一监测周期停止追加和升压，有界诊断并关闭本次资源；列出成功/失败/未完成及420秒后晚到结果，后者不算闸门内成功；成功子集P50/P95必须附样本数，全体分位数无法确定时标为未知或明确下界

#### Scenario: 结束后核验资源
- **WHEN** 测试正常完成、失败、取消或触发闸门
- **THEN** 按PID/出生身份核对自有服务、worker与监听释放至少5秒，原共享服务保持；强制回收须报告关闭失败，日志与质量证据保留
