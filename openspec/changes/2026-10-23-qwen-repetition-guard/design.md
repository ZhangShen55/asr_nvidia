# Design

## Context

### 复读幻觉的复现与归因

来自 `docs/qwen-asr-v2-throughput-benchmark-20261023.md` §5.2（该节的结论已按生产同款 pydub 转码链路复现后修正）：

- 同一段音频（`思想道德与法治_2424101_2424102_董金平` 的 1715.85~1721.80s 段）在 c16 / c32 档位产出 1863 字符的「最小S零，这个这个这个这个，……」；
- **该段单独发给 Qwen 也必然复读**——并发只改变被截断的长度（128 路并发下在 1633 / 1940 之间波动），不决定是否发生；
- 根因是 vLLM 的 batched 推理跨 batch shape 非逐位确定（`vllm:num_requests_*` 变化），同一段音频在不同批次的解码路径不同；`temperature` 在 vLLM `TranscriptionRequest` 默认为 0.0（贪心），差异不是采样随机性；
- 复读段撞上 `max_model_len = 1024` 后被截断，对应 `finished_reason=length`；
- VAD 本身完全稳定：同一文件永远切出 943 段，跨档位 ±1~2 段的差异来自 Qwen 侧空文本段数量波动，不是 VAD 抖动。

### 已有的检测与修复实现

`utils/repetition.py` 已实现（提交 `d3a60f3`），当前仅离线使用，未接入接口：

| 组成 | 内容 |
|---|---|
| `max_reasonable_chars(duration_s)` | `max(120, duration_s × 40)` |
| `find_repeat_loop(text, min_unit, min_times)` | 找出最长的连续重复片段，返回 `(单元, 单元长度, 重复次数)`；扫描时按单元长度降序，找到即返回 |
| `collapse_repetition(text, ...)` | 三级放宽折叠 `(4,3) → (2,4) → (1,6)`，每级最多折叠 12 轮 |
| `repair_repetition(text, duration_s)` | 长度正常原样返回；超长则折叠；超长但无复读结构时保留原文并告警 |

阈值标定依据（68,018 段真实样本）：正常段 p99.9 = 20.3 字符/秒、最高 26.2；复读段 282~313。取 40 留约 1.5 倍余量且远低于复读量级。

离线回归结果：68,018 段中仅修复 4 段（全是同一个幻觉），**零误伤**；1863 字 → 7 字「最小S零，这个」。正常叠词「这个这个这个这个」「温度载荷，温度载荷，温度载荷，」与长英文句均未被改动。

### v2 链路的文本处理顺序

`api/routes/asr_qwen_common.py` 当前的文本流依次为：

1. Qwen 原始输出 → `parse_qwen_text()` 剥离 `language <语种><asr_text>` 前缀；
2. 解析结果写入 `SegmentOutcome.text`（落地点在 `:497` 附近）；
3. ITN 规范化 `normalize_segments()`（`:521`）；
4. 标点卫生 `sanitize_segments()`（`:525`）；
5. 响应组装。

## Goals / Non-Goals

**Goals:**

- 把已有的复读检测与修复能力接入 `/v2/seacraft_asr` 的在线链路，让 1863 字符的复读段在响应中变成正常长度的文本。
- 保证对正常文本零影响（不改写、不截断），并让误伤风险可度量、可回归。
- 让阈值可配置，且默认值有真实样本的标定依据。
- 让每次折叠都可追溯（日志含原长度、折叠后长度、时长上限、时长）。

**Non-Goals:**

- 不试图从模型侧消除复读（不改 `max_model_len`、`temperature`、不调 Qwen 服务参数）。
- 不改变复读的归因结论，也不引入新的解码策略。
- 不处理跨段的复读（同一句话在多个相邻分段反复出现）——本变更只处理单段内部的生成循环。
- 不构建镜像、不部署上线。

## Decisions

### 决策 1：接入点选在 ITN 之前

**选择**：在 `SegmentOutcome.text` 落地处（即 ITN 规范化之前）执行复读检测与修复。

**理由**：

1. 复读是 Qwen 原始输出就带的，ITN 不会制造复读——在原始输出上判定最贴近问题本质；
2. ITN 会改写数字（「二零二五」→「2025」），改变字符数，可能让「字符数 ÷ 时长」的判据偏移；在 ITN 之前判定，判据面对的是模型的原始语速；
3. ITN 之后还有标点卫生规则在改动文本，若先折叠再 ITN、再标点卫生，三步的先后关系需要明确定义；把最靠前、最确定的一步放在链路最前端，后续两步的行为不受影响。

**替代方案**：放在 ITN 之后。好处是判据面对的是最终呈现文本，坏处是 ITN 的改写会污染长度判据，且需要在 ITN 之后才知道最终时长对应的字符数——收益不明显，否决。

### 决策 2：只用「长度异常 + 复读结构」双条件触发

**选择**：仅当分段文本长度超过合理上限 **且** 检出连续重复结构时才折叠；长度超限但未检出结构的文本保留原文并告警。

**理由**：单靠长度判据无法区分「复读」与「说得极快但内容真实」的长段——真实语速上限约 26.2 字符/秒，而复读是 282~313，两者差一个数量级，40 字符/秒的阈值足以把两者分开；但反过来说，一个语速恰好 35 字符/秒的真实长段可能被误判。单靠复读结构判据也不行：真实的重复口语（「温度载荷，温度载荷，温度载荷」）结构上就是复读。双条件同时成立才动手，误伤概率最低。

**保留告警而非静默放过**：超长但无复读结构是一个「需要人看一眼」的信号——可能是真长段，也可能是模型产出了我们尚未识别的异常模式。告警让这类样本可见，但不改变内容。

### 决策 3：阈值外置到配置，标定依据写进规格

**选择**：新增配置项（启用开关、字符数上限系数、最小重复单元长度、最小重复次数、绝对最小字符数），默认值为 40 字符/秒与 `(4, 3)`。

**理由**：项目规格要求「运行参数 MUST 全部来自配置文件，MUST NOT 硬编码」。同时把标定依据（正常段 p99.9 = 20.3、峰值 26.2、复读段 282~313）写进规格，使得后续调整阈值的人知道在动什么，而不是随手改一个数字。

### 决策 4：折叠后仍超长时保留折叠结果并告警

**选择**：折叠一次后若文本仍超过上限，不再做第二轮截断，保留折叠结果并告警。

**理由**：真实的复读结构通常只有一层，折叠一次即可回到正常长度。若折叠后仍超长，说明该段存在嵌套更深的循环或多层结构，此时继续折叠可能破坏内容；保留并告警让人工介入比继续动刀安全。实现上 `collapse_repetition` 本身已有「折叠后长度不小于原长度则停止」的保护。

### 决策 5：日志只记录前缀，不记录全文

**选择**：告警日志包含原长度、折叠后长度、时长上限、时长，以及原文本的前若干字符作为定位线索。

**理由**：复读段可达数千字符，全文入日志会淹没日志文件并可能包含用户语音内容。前缀足以定位问题段落。

## Risks / Trade-offs

- **[误伤真实的长段]** → 双条件触发 + 68,018 段零误伤回归 + 阈值可配置 + 告警可见。上线后用真实音频再跑一轮逐段比对作为兜底。
- **[折叠掩盖了真实的重复口语]** → 折叠只在长度异常时触发；真实重复口语（「温度载荷，温度载荷，温度载荷，」）长度正常，不会被触发。已被离线回归覆盖。
- **[ITN 与复读修复的先后被后续改动打乱]** → 接入点固定在 `outcome.text` 落地处，并在代码注释中标注「复读修复必须在 ITN 之前」，同时用单元测试锁定顺序。
- **[阈值随业务语种变化而失效]** → 中文约 4~6 字/秒、英文约 12~16 字/秒，40 字符/秒的系数对两者都留有余量；若将来出现更快的语种（如密集代码朗读），需要重新标定——标定依据已写进规格，便于复算。
- **[被折叠的文本可能丢失信息]** → 只在复读结构成立时折叠，折叠保留首份内容（「最小S零，这个这个这个」→「最小S零，这个」），不丢弃有效前缀。

## Migration Plan

1. **配置先行**：在 `config.toml` / `config.docker.toml` 中新增复读修复相关配置，默认启用。
2. **代码接入**：`api/routes/asr_qwen_common.py` 在 `outcome.text` 落地处调用 `utils/repetition.py`；`utils/repetition.py` 补齐「配置驱动的阈值」接口（当前阈值是模块级常量，需改为可传入）。
3. **后端运行与验证**：跑单元测试；用 `test/audio_file/` 中的真实音频跑一遍，逐段比对响应文本与接入前的差异，确认只有复读段发生变化。
4. **回滚策略**：把复读修复开关设为 false 即完全关闭该行为，响应回到接入前状态。
5. **不在本次范围**：镜像构建与部署上线另行确认后执行。
