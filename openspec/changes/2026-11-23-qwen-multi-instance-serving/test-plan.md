# 正式服务验收计划

## 固定输入和口径

本目录`test-inputs.json`已固化既有实验`/tmp/qwen200-20261123-j9r2czoi/assets/inputs-six.json`的原a1～a6；path_bytes_b64为路径字节权威值，display_path便于阅读，按该清单定位输入，先核验manifest实际存在、源绝对路径、全文件SHA256、时长和声道；缺失只能按历史已记录SHA找回，不能随意换短文件。A4/B4固定同一a1～a4。保存正式commit、源码hash、配置解析值、保护模块实际导入路径、驱动/依赖版本、当前共享NPU负载，不修改依赖。

输入必须是原完整WAV，v3真实HTTP、并发起跑；计时不含独立暖身，但包括请求内真实VAD/裁剪、模型、聚类/ITN和序列化，不能预切好段代替。计时定义：每请求从HTTP发送至完整响应接收；墙钟从第一请求发送至最后响应接收，另列最大请求时延。P50/P95统一使用线性插值方法并记录n，不能混合不同轮次/模式。

## 阶段0：无NPU回归与部署前检查

- 配置N/S边界、类型、派生容量、相等旧值提示/冲突拒绝、legacy显式兼容、N小于4时B有效值、预算作用域，根/Docker解析一致。
- 动态租约：随机路径、同文件并发、乱序、连续两轮复用、总/B容量与队列、授予/取消/关闭竞争，无SHA/测试开关。
- 逐段独立EOS/refill；每owner≤S、总≤N×S，提前结束不受慢段阻塞；每owner设备步单owner；PCM三分支终态，Qwencredit可先返。
- 部分预加载失败回滚、owner进程死亡/全部失效、在途cancel与重复收尾、状态只读、真实资源释放；保留复读/长度异常恢复和段警告语义。
- B并发Task、过滤/emo边界、异常降级和真实字段测试；不能仅镜像实现写断言。
- 按AGENT完整r4+candidate+support guard运行适当源码回归及实际保护.so目标回归；导入前设置各自TMPDIR/stats/cache，记录拦截和模型/设备执行为零。CPU关闭后才进入NPU，禁止同时压力。

## 阶段1：正式服务与实例覆盖

使用改造后的正式源码及最终部署配置，单HTTP服务、N6、npu7、S16；临时独立端口18083使用前检查，无占用才启动。本轮每个PID及后代记录birth、模块路径、配置快照；共享服务PID1601397不碰。每个Qwen owner均完成真实短clip forward/prefill，状态显示6健康，暖身后检查窗口和PCM归零。默认顺序加载及启动/失败回滚另有独立证据，READY不算暖身。

## 阶段2：A6基准

不请求增强的原a1～a6六路同时v3，使用新正式默认。保存6份完整响应、错误/警告/状态与各音频阶段时间。验证租约唯一、每owner16、全局96、独立完成补位与回收。A6约200秒是目标；即使全部HTTP200也报告warning-free成功数和discard段数。此轮不以实验194.81替代。

## 阶段3：A4对照、B池标定与B4

1. 同源a1～a4先跑A4，保存完整结果与计时。
2. 保持全部6份Qwen驻留；CAM/emo各1起步，逐池依据真实等待和资源标定到2/4，非盲扫组合。每次用配置重启时重新证明6owner暖身，冷加载与暖性能分列，标定失败保留。标定只能调整池配置，不改生成/VAD/文本策略。
3. 选定增强池规模后冻结根/Docker最终配置。B4每条showSpk=true、showEmotion=true、showRoleIdentify=false，四条完整WAV共同起跑；每份配置增强实例须有真实NN调用证据，不能只看加载。
4. 验证CAM对有效段的覆盖，emo1～10秒真实调用，其他时长平淡并计skip。统计实际成功/失败/skip、空embedding、聚类/情绪字段和归属一致性；部分降级HTTP200明确单列，不能算严格增强完整成功。
5. 准入探针与性能轮分开：4B后第五B4017，4B+2A可准入；总6满后新A/B4013优先；能力关闭/实例不可用/队列超时保持原错误。探针结束并窗口归零再计时。

## 阶段4：增强共驻A6

B4暖态完成后保留六份Qwen及所选CAM/emo池驻留，再对同a1～a6发纯A6，检验现实服务后续A类效率和HBM。与纯A6分开报告，不把不同状态合并分位数。最终交付配置必须是实际验收配置；如标定改变配置，必要轮次用冻结值复验，不能用低池数成绩交付高池数。

## 分阶段指标与输出差异

每轮记录完整响应n/N、业务成功、warning-free成功、段恢复/不可恢复、HTTP/业务码、P50/P95/墙钟、完整与删失名单。未全部完成时全批P50/P95标未知，仅另列完成子集n的统计；记录取消发生时刻，不等价认定所有未返回均慢于336秒。

计时拆分：解码准备、VAD及其队列、裁剪及线程等待、owner租约等待、Qwen提交/prefill/decode/读回、CAM/emo池等待/实际调用、分支join、聚类、ITN、输出；未独立测得项明确unknown，不能跨worker累计相加解释墙钟，gpu_time_ms保留旧含义。

资源：每owner active/prefill分布、KV与allocator allocated/reserved峰、卡HBM free/used时序、CAM/emo及host/swap、采样间隔和缺口；共卡外部进程影响单列，HBM不可按权重数简单估算。测量工具不得引入额外模型加载或请求路径阻塞。

质量：保存全部最终文本及段边界/说话人/情绪；与同源六音频noHBM参考做逐段完整差异，列实际变更文本、丢失/新增/边界变化和warning，禁止只给相似度。A4/B4对照核查增强不改变文本归属。算法未改仍可能因调度改变文本，无人工真值则质量未认证，不承诺98%召回。

## 停止与回收

所有正式轮次保留336秒、推理OOM/owned故障/明确无进度停止并采证；超过200但未到336如实标目标未达，不凭感觉提前给成功结论。已取消free-HBM<8GiB提前停止，不恢复、不另设替代free阈值；持续记录真实内存和故障。任何停止条件触发立即停止当前批和后续压力，先诊断，不自动换档重试。

计划内共驻阶段之间只排空窗口与PCM，保持同一健康服务和权重驻留；服务生命周期结束或任一停止条件触发时拒绝新请求、等待设备及三路终态并正常关闭；模型grace120秒、外层210秒、HTTPdrain30秒。记录所有owned PID/birth实际消失、退出码、端口持续空闲≥5秒、私有PCM为空、共享PID1601397及其端口保留、NPU回到相近背景。强制兜底、超时或退出1不能算正常关闭；日志/临时stage保留，不rm-rf。

## 报告与通过条件

报告必须区分功能通过、性能目标、质量警告和正常关闭。A6完整6/6且真实默认/容量契约成立为功能门槛，约200秒目标单列；B4真实双增强覆盖4/4或明确未达/降级，不能仅用HTTP200。任何未通过不勾对应任务。B4不预设200秒成绩，不以不同工作量A6/B4墙钟直接算增强开销。
