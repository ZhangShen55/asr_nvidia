# SeaCraftASR 上游对接文档

> 接口版本：v3（`/v3/seacraft_asr`）  
> 文档日期：2026-11-10 
> 适用对象：调用本离线语音转写服务的上游业务方

## 1. 接口与地址

| 方法 | 路径 | 说明 |
|------|------|------|
| `POST` | `/v3/seacraft_asr` | 离线 ASR 转写（业务接口） |
| `GET` | `/get_status` | 服务状态，可用于健康检查 |

服务地址：本地调试 `http://10.80.5.130:8081`(注意：现在并未部署)。

转写接口是**同步阻塞**的：一次 HTTP 请求即对应一次完整的转写任务，没有异步提交 / 回调接口。

## 2. 转写接口

| 项 | 值 |
|----|----|
| 方法 | `POST` |
| 路径 | `/v3/seacraft_asr` |
| Content-Type | `multipart/form-data` |
| 请求体 | 表单字段，音频以文件字段 `audioFile` 上传 |
| 响应 Content-Type | `application/json` |

### 2.1 请求参数

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| `audioFile` | 文件 | **是** | — | 音频文件。支持 `wav / mp3 / m4a(mp4) / aac / flac / ogg` 等 ffmpeg 可解码格式，服务端统一转成 16 kHz 单声道 PCM16 后处理 |

> **只需要传 `audioFile` 一个参数，其它字段都不用传。**
>
> - `language`：不要传。这个版本没有语种约束，为了兼容之前版本，不传即为 `auto`（自动识别）。
> - `showSpk` / `showEmotion` / `showRoleIdentify` / `wordTimestamps` / `hotWords` 等历史字段：本次对接
>   都不需要传，默认行为即为期望行为，传了也不影响输出。其中 `showSpk` / `showEmotion` 只适用于「智评」。

### 2.2 音频要求

- **格式**：服务端会转码，调用方无需自行处理；但转码有额外开销，建议直接提供 16 kHz / 单声道 / PCM16 的 wav。
- **大小**：生产环境 Nginx 的上传上限为 1 GB；转码后音频小于 1 KB 会被判为空音频，返回 `4006`。
- **时长**：单次请求可提交整段录音。长音频建议按 ≤ 30 分钟切片后多次提交（理由见 4.3）。
- **内容**：静音或无人声的音频在 VAD 阶段返回 `4008`。

### 2.3 请求示例

```bash
curl -X POST "http://<host>:8081/v3/seacraft_asr" \
  -F "audioFile=@classroom.wav"
```

### 2.4 响应

成功响应（节选）：

```json
{
  "language": "Chinese",
  "segments": [
    {
      "segment_text": "同学们好，今天我们讲一下分布式系统的设计。",
      "bg": "0.52",
      "ed": "6.34",
      "speed": 178,
      "segment_words": [],
      "role": null,
      "emotion": null
    },
    {
      "segment_text": "老师，这个和一致性哈希有什么区别？",
      "bg": "6.90",
      "ed": "11.20",
      "speed": 195,
      "segment_words": [],
      "role": null,
      "emotion": null
    }
  ],
  "text": "同学们好，今天我们讲一下分布式系统的设计。 老师，这个和一致性哈希有什么区别？",
  "speed_info": [
    { "unit": 1, "segment_info": { "segment_count": 12, "speed": [181, 165, 190] } },
    { "unit": 5, "segment_info": { "segment_count": 3, "speed": [180, 176, 183] } },
    { "unit": 10, "segment_info": { "segment_count": 2, "speed": [179, 181] } }
  ],
  "load_audio_time_ms": "42.18",
  "gpu_time_ms": "9123.47",
  "language_ratio": { "zh": 100.0 }
}
```

顶层字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `language` | 字符串 | 主导语种全称（如 `Chinese` / `English` / `Cantonese`）；无法判定时返回 `auto` |
| `segments` | 对象数组 | 分段结果，见下表 |
| `text` | 字符串 | 全部最终保留分段的文本，用**单个空格**拼接。已做 ITN 规范化与标点清理 |
| `speed_info` | 对象数组 | 按 1 / 5 / 10 分钟窗口的语速统计 |
| `language_ratio` | 对象 | 各语种文本字符占比（百分比，保留一位小数，合计 100.0）。键为语种简写 `zh` / `en` / `yue` … |
| `load_audio_time_ms` | 字符串 | 音频读取 + 转码耗时（毫秒） |
| `gpu_time_ms` | 字符串 | 本次请求端到端处理耗时（毫秒） |

`language_ratio` 的键为语种**简写**，取值如下（模型返回的语种名不在表中时原样透传，例如 `auto` 或模型自造标签）：

| 语种 | 简写 | 语种 | 简写 | 语种 | 简写 |
|------|------|------|------|------|------|
| Chinese | `zh` | English | `en` | Cantonese | `yue` |
| German | `de` | Italian | `it` | Portuguese | `pt` |
| Spanish | `es` | French | `fr` | Thai | `th` |
| Malay | `ms` | Japanese | `ja` | Korean | `ko` |
| Russian | `ru` | Hindi | `hi` | Arabic | `ar` |
| Vietnamese | `vi` | Indonesian | `id` | Dutch | `nl` |
| Turkish | `tr` | Polish | `pl` | Greek | `el` |
| Hebrew | `he` | | | | |

占比按**字符数**统计（不含空白），保留一位小数，各语种之和为 100.0；没有有效文本时 `language_ratio` 为空对象 `{}`。
顶层 `language` 字段仍返回模型返回的语种全称（如 `Chinese` / `English` / `Cantonese`），与 `language_ratio` 的键不是同一套取值。

`segments[]` 字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `segment_text` | 字符串 | 该段的转写文本 |
| `bg` | 字符串 | 段起始时间，单位秒，保留两位小数（如 `"6.90"`） |
| `ed` | 字符串 | 段结束时间，单位秒，保留两位小数（如 `"11.20"`） |
| `speed` | 整数 | 该段语速（内容单位 / 分钟）。中文按字计，其余语言按词计 |
| `segment_words` | 数组 | 词级时间戳，恒为 `[]` |
| `role` | `null` | 说话人角色，本次对接不启用，恒为 `null` |
| `emotion` | `null` | 情绪标签，本次对接不启用，恒为 `null` |

`speed_info` 结构：

```json
{ "unit": 5, "segment_info": { "segment_count": 3, "speed": [180, 176, 183] } }
```

`unit` 为窗口长度（分钟），取 1 / 5 / 10；`segment_count` 是切分出的窗口数，`speed` 是每个窗口的语速数组。
跨窗口的句子按与窗口的时间重叠比例分摊。

### 2.5 结果使用

- 展示字幕：用 `segments` 的 `bg` / `ed` + `segment_text`，不要用 `text` 二次切分时间轴。
- 只要全文：直接用 `text`。

## 3. 错误码

**业务错误的 HTTP 状态码仍然是 `200`**，错误信息在响应体的 `code` / `msg` 字段中。上游必须解析 `code`
再判断成功与否，不能只看 HTTP 状态码。成功响应里没有 `code` 字段；失败响应只有 `msg` 与 `code`。

| `code` | `msg` 示例 | 含义 | 可重试 |
|--------|-----------|------|--------|
| `4001` | 音频文件不能为空 | 未携带 `audioFile` | 否 |
| `4002` | 读取音频文件发生错误 | 文件损坏或无法解码 | 否（需换文件） |
| `4003` | Qwen 转写能力未开启 | 服务端能力开关关闭 | 否（联系服务方） |
| `4005` | 未知错误 | 服务内部异常 | 是 |
| `4006` | 音频文件内容为空，请重新录制 | 转码后音频 < 1 KB（空白音频） | 否 |
| `4007` | 音频分块失败，请重试 | 服务端裁剪片段失败 | 是 |
| `4008` | 音频文件为空或未检测到任何人声 | 静音 / 无人声 / 全被过滤 | 否（需换文件） |
| `4010` | 请求排队等待超时 | 等待队列等待超时 | 是 |
| `4011` | Qwen 服务不可用或未发现可用模型 | 依赖的转写服务异常 | 是 |
| `4012` | Qwen 服务调用失败，请稍后再试 | 超时 / 连接错误 / 重试耗尽 | 是 |
| `4013` | 处理队列已满，请稍后再试 | 音频并发满 | 是 |
| `4014` | VAD 池异常 | VAD worker 池不可用 | 是 |

只重试 `4010` `4011` `4012` `4013` `4014`，其余是请求本身的问题，重试无意义。

非 200 的 HTTP 响应：

| 状态码 | 场景 | 上游应对 |
|--------|------|----------|
| `404` | 路径写错，现在是不是`v1.1.8` `/v3/seacraft_asr` |
| `405` | 方法不对（例如对 `/v3/seacraft_asr` 发 GET） | 改用 `POST` |
| `413` | 上传文件超过 Nginx 上限（1 GB） | 切分音频 |
| `422` | 表单缺必填字段（最常见是漏了 `audioFile`） | 补齐表单字段 |
| `500` | 服务内部异常 | 重试；持续失败则联系服务方 |

## 4. 并发与超时

### 4.1 并发额度

音频并发默认 8，超出返回 `4013`。**服务不会阻塞等待**，容量满时立即返回错误码，上游需要自己做退避重试。


### 4.2 长音频与幂等

- **长音频**：单次请求可提交整段录音，但超时随时长线性增长，且失败后重试的代价同样放大。
  建议按 ≤ 60 分钟切片后多次提交。
- **幂等**：接口没有幂等键，同一份音频重复提交会被当作多个独立任务，重复占用额度并重复计费。
  上游重试时需自行去重（例如按文件哈希或业务流水号记录在途状态）。

### 4.3 健康检查

```bash
curl -fsS http://<host>:8081/get_status > /dev/null && echo ok
```
