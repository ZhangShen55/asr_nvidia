# 模型内存压力与 Swap 诊断测试报告

## 结论

本次诊断没有发现 OOM、SeaCraftASR 崩溃、VAD worker 孤儿进程或缓存持续泄漏。主要卡点是同一张 `cuda:0` 上的 CAM++/emotion2vec 实例池排队：8 路请求、每个音频 7 个有效段时，Qwen 等待几乎为零，而 CAM++ 和 emotion2vec 等待累计均约 117 秒，模型池当前 3:1 的实例比例会直接形成 3 个 CAM 槽位和 1 个 emotion2vec 槽位的 FIFO 排队。

安全闸门最终因连续 Swap I/O 停止继续升压。停止时可用内存仍约 16.3 GiB，8085、4 个 VAD worker 和 8806 均健康，因此停止动作避免了进一步施压，没有造成服务需要手动恢复。

## 受控阶段结果

为避免长达约 47 分钟的完整课堂音频在监控代码验证阶段造成不可逆压力，本轮使用同一课堂音频中截取的 20 秒有声片段复制为 8 个独立文件，验证模型加载、段级并行和安全闸门；工具仍支持传入完整 WAV 目录进行正式长音频测试。

本轮烟测阶段使用 5 秒冷却以缩短已受保护的验证窗口；最高档位结束后另行执行了 60 秒无请求冷却采样，确认 PSS、Swap 和缓存状态。

| emotion2vec 单独加载 | 1 | 1 | 0.425 s | 0.425 s | 1.503 GiB | 15.39 GiB |

## 阶段耗时归因

`/get_status.resourceDiagnostics.requestTelemetry` 在 27 个请求事件（其中 4 个是首次无有效 VAD 片段的 4008 探针请求）上的累计 P50/P95 如下。阶段字段是单个请求内各 VAD 段耗时的累计值：

| 阶段 | P50 | P95 | 说明 |
| --- | ---: | ---: | --- |
| VAD | 104 ms | 559 ms | 没有形成主要瓶颈 |
| 裁剪累计 | 134 ms | 362 ms | 受段数影响，但墙钟 P95 仅 60 ms |
| Qwen 等待 | 0.021 ms | 0.047 ms | 没有排队迹象 |
| Qwen 推理累计 | 1.176 s | 2.183 s | 有计算耗时，但不是当前主要排队点 |
| CAM++ 等待 | 1.330 s | 15.673 s | 3 个实例在 8 路请求下排队 |
| CAM++ 推理 | 0.867 s | 2.077 s | 同卡算力会放大尾延迟 |
| emotion2vec 等待 | 2.413 s | 15.339 s | 单实例是最明显的 FIFO 排队点 |
| emotion2vec 推理 | 0.270 s | 0.725 s | 单实例完成后立即释放槽位 |
| 聚类 | 0.5 ms | 7.9 ms | 已不是旧版 O(n⁴) 卡点 |
| 缓存清理 | 0.5 ms | 0.9 ms | 本轮最终回到 0 文件 |

模型池累计计数为：CAM++ 102 次调用、等待 117,175.72 ms、推理 29,609.95 ms；emotion2vec 102 次调用、等待 117,313.63 ms、推理 7,025.12 ms。两者 `busy=0`、`waiting=0` 收尾，说明槽位释放后可以继续接收后续段，没有发现释放间隙造成的长期占用。

## 内存、Swap 和缓存证据

- VAD 预热后、模型尚未加载时后端 PSS 约 0.28 GiB；CAM++ 加载后约 1.49 GiB；emotion2vec 加载后约 1.50 GiB。模型常驻和 Python/PyTorch 运行时是主要基线，而不是单纯权重文件大小。
- 8 路阶段后端 PSS 峰值约 1.646 GiB，60 秒无请求冷却采样保持约 1.652 GiB，未继续上升；这次短片段测试不能证明长音频无增长，但没有看到持续线性泄漏。
- 测试开始 Swap 已使用约 11.42 GiB，最高约 11.55 GiB，增量约 132 MiB。绝对值来自测试前环境，诊断使用增量判断；连续 `pswpin/pswpout` 触发了红色闸门。
- `/tmp/seacraft_asr` 基线为 0 文件；请求期间最多观测到 1 个约 625 KiB 文件；最终及 60 秒冷却后均为 0 文件。
- 没有出现可用内存低于 `max(8 GiB, 总内存 20%)`、OOM 或 VAD worker 数量下降。

## 一次误报和修正

首次运行在 emotion2vec 冷加载期间因为 `/get_status` 采样超过 2 秒触发“后端健康检查连续失败”，但后端进程和 VAD worker 实际仍健康。诊断工具已改用轻量 `/openapi.json` 作为健康探针，保留 `/get_status` 作为资源和模型池快照，避免把慢状态采样误判成服务故障。该次现场同样保存，Qwen 8806 未受影响。

## 结论与后续建议

1. 当前 8 路并发的首要瓶颈是 CAM++/emotion2vec 的独立模型池排队，尤其 emotion2vec 只有 1 个实例；`segment_concurrency=16` 会让更多段进入在途任务，但不会增加模型槽位。
2. 8 路短片段阶段的 P95 仍低于 3.6 秒，不能外推到完整 47 分钟课堂音频；完整音频应在已加载模型、Swap 清零或固定基线的隔离机器上逐档执行，并保留 60 秒冷却。
3. 后续优化候选按证据排序：先评估 CAM++/emotion2vec 实例比例和设备分配，再评估段级有界队列、请求对象释放和音频 Tensor 引用生命周期；不要仅提高 `segment_concurrency`。
4. 生产侧应保留本次安全闸门和 1 秒采样，但把长期准入控制另立 change；本 change 不自动修改实例数量、VAD 算法或 Qwen 配置。
