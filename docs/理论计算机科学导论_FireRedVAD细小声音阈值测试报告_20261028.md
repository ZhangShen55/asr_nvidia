## 一、测试目标

JSON 中有 46 个“细小声音”标注。本次固定模型和音频，只测试三个 `speech_threshold`：

```text
0.5、0.6、0.7
```

判定规则：

- **有重叠检测到**：FireRedVAD 任意一个分段与标注区间有超过 0 秒的时间重叠；
- **覆盖一半检测到**：FireRedVAD 最佳重叠段覆盖标注区间至少 50%；
- **覆盖 80% 检测到**：用于观察是否只是擦边重叠，不能单独作为准确率。

这里的“检测到”是时间重叠判定，不等同于模型识别出了“细小声音”的语义。

## 五、测试结论

如果你的目标是“尽量不要检测到 JSON 标注的细小声音”：

1. 在本次三个阈值中，`speech_threshold=0.7` 效果最好，未发生重叠的标注最多，为 15/46。
2. 但 `0.7` 仍然检测到 31/46 个标注，不能满足“这些细小声音基本都不被检测到”的目标。
3. 从 0.5 提高到 0.7，只减少了 5 个有重叠标注，收益有限。
4. 阈值提高后整体覆盖率下降，但分段数增加、短段增加，说明它不是简单的“过滤更多声音”，还改变了语音边界和切分方式。

因此，当前不建议仅通过把 `speech_threshold` 提高到 0.7 来解决问题。下一步应优先确认：

- 这些“细小声音”是否确实位于独立的弱能量区间；
- FireRedVAD 是否把它们并入前后正常语音段；
- 是否需要使用 `min_speech_frame`、`min_silence_frame`、`merge_silence_frame` 等参数控制短段合并；
- 提高阈值后是否误删了正常英文弱读、短词和课堂回应。

## 六、建议的下一轮验证

建议以 `speech_threshold=0.7` 为起点，再做参数组合测试：

```text
speech_threshold = 0.7
min_speech_frame = 20 / 30 / 40
min_silence_frame = 20 / 30 / 40
merge_silence_frame = 0 / 10 / 20
```

每组同时统计：

- 46 个“细小声音”的检测数；
- 正常语音段是否被误删；
- 总分段数和短段比例；
- 语音覆盖率；
- Qwen-ASR 文本是否缺字。

本次测试未修改生产配置、VAD 代码或 Qwen-ASR 服务。
