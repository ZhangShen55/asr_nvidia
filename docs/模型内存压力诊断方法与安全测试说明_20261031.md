# 模型内存压力诊断方法与安全测试说明

## 范围

本 change 用于确认 CAM++、emotion2vec、VAD worker、音频缓冲、Swap 和 GPU 争用分别对卡顿的贡献。已确认正常的 VAD-only A 项跳过；诊断只访问 SeaCraftASR 8085 和 Qwen-ASR 8806 的健康接口，收尾阶段不得停止或重启 Qwen。

## 一次运行的证据

运行目录由 `scripts/model_memory_pressure_diagnostics.py` 生成：

- `metadata.json`：run ID、UTC 时间、Git 提交号、配置快照、模型设备数组、VAD 数组和阶段矩阵；
- `snapshots.jsonl`：基线和每秒资源快照，进程异常时已写入的行仍可读取；
- `stage-*.json`：每个阶段的请求数量、成功/失败、P50/P95 和资源峰值；
- `run-summary.json`：安全终止事件、最终回收状态、PSS/缓存斜率和模型池等待归因。

缺失指标统一使用 `available=false` 和 `reason` 表示。`0` 只表示采集成功且实际为零。

## 关键字段和判定

| 证据 | 读取位置 | 判定用途 |
| --- | --- | --- |
| 主机可用内存 | `/proc/meminfo` 的 `MemAvailable` | 低于 `max(8 GiB, 总内存 20%)` 立即停止 |
| 进程真实贡献 | `/proc/<pid>/smaps_rollup` 的 PSS/Private | PSS 斜率用于识别请求后未释放；RSS 仅作辅助 |
| 换页 | `/proc/meminfo` 的 SwapUsed、`/proc/vmstat` 的 `pswpin/pswpout` | 以测试开始值为基线；增量超过 256 MiB 或连续 3 个采样周期有 I/O 时停止 |
| GPU | `nvidia-smi` 显存、利用率和计算进程 | 显存使用率达到 90% 停止；主机内存稳定而利用率高且模型等待上升时归因同卡算力争用 |
| VAD worker | 进程名 `asr-offline-vad` 和 `/get_status.vadPool` | 数量低于配置数量时停止，避免孤儿 worker 继续占用资源 |
| 缓存 | `/tmp/seacraft_asr` 中 `seacraft-asr-*` 文件 | 阶段结束后文件数和字节数应回到基线附近；持续增长指向清理/引用释放问题 |
| 模型池 | `/get_status.localModels` | `waiting`、`wait_total_ms`、`inference_total_ms` 分别定位 CAM++/emotion2vec 排队和推理耗时 |
| 请求阶段 | `/get_status.resourceDiagnostics.requestTelemetry` | 记录总时延、VAD、裁剪、Qwen 等待/推理、CAM++ 等待/推理、emotion2vec 等待/推理、聚类和 ITN 的 P50/P95 |

## 安全阶段

1. CAM++ 单独加载（`showSpk=true`）；
2. emotion2vec 单独加载（`showEmotion=true`）；
3. 两个模型同时加载；
4. 2、4、8 路完整音频逐级测试；
5. 每阶段完成后冷却 60 秒，并确认后端健康、VAD worker 数量、缓存和 Swap 回落后才进入下一阶段。

工具不在线修改生产配置。`segment_concurrency=4/8/16` 需要使用隔离后端配置分别重启后重复运行；运行元数据会记录启动时实际值，避免把未切换的配置误报为测试结果。

## 红色终止动作

触发红色条件后，工具设置停止标志，不再提交新请求；等待已提交请求返回并写入现场，随后读取最终进程、缓存和 8085/8806 健康状态。默认不发送进程信号；只有显式传入 `--stop-backend-on-red --backend-pid PID` 才向 SeaCraftASR PID 发送 SIGTERM。工具没有任何停止或重启 8806 的分支。

## 归因规则

- 模型单独加载就接近内存安全水位：模型常驻内存是首要约束，应减少实例或拆分设备；继续提高并发不会解决该问题。
- 单路稳定、多路时 PSS 随并发上升，阶段结束缓存回落：优先归因音频/段级在途缓冲。
- 连续请求结束后 PSS 斜率仍为正、缓存也不回落：优先检查对象引用、任务列表和异常路径清理。
- 主机内存和 Swap 稳定、GPU 利用率接近饱和且 CAM++/emotion2vec 等待增加：优先归因同卡算力争用。
- Qwen 等待 P95 单独升高而本地模型等待稳定：归因 Qwen 端队列或服务吞吐，不能把它归为本地模型池。

## 复现命令

```bash
cd /home/zhangs/workspace/asr_nvidia
conda run --no-capture-output -n asr \
  python scripts/model_memory_pressure_diagnostics.py \
  --base-url http://127.0.0.1:8085 \
  --qwen-url http://127.0.0.1:8806 \
  --audio-dir /home/zhangs/workspace/asr_nvidia/test/audio_file/音频文件 \
  --out-dir /tmp/seacraft-model-memory-diagnostics \
  --cooldown-s 60
```

仅生成阶段计划和配置快照：

```bash
conda run --no-capture-output -n asr python \
  scripts/model_memory_pressure_diagnostics.py --plan-only
```
