## 正常关闭与为何没有继续CAM2/4

`shutdown.json`：exit0、forced=false、orphan_cleanup=false、remaining_pids为空、私有cache为空、端口持续观察5秒无监听。全部本轮owned资源正常关闭；resident在停止后的中间状态仍有在途工作，与最终安全关闭不矛盾。

`run.json`的卡7背景观测：启动前used15908/free49628MB；关闭后used15910/free49626MB，used差+2MB。既有PID1601397报告占用前后均12417MB，owned_normal_exit=true；控制器把near_background保留unknown而未以小差值自动冒称验证通过，原始数值与共享变动需root复核。

计划允许“单CAM出现瓶颈再标定2/4”，同时规定真实OOM/故障立即停止当前和后续压力。本轮各1共驻路径已经发生明确OOM，因此不能为了完成池规模矩阵继续增加CAM副本。未进入2/4是遵守已批准故障停止条件，不是恢复取消的8GiB free-HBM线，更不能声称各2/4已被判定不可行。
