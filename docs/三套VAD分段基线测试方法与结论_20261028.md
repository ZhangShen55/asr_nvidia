# 三套 VAD 分段基线测试方法与结论

日期：2026-10-28
测试目录：`/home/zhangs/workspace/asr_nvidia/test/audio_file/音频文件/`
样本：45 个 WAV，全部为 16 kHz、单声道、16 bit，总时长 136,419.79 秒（约 37.89 小时）

## 一、测试目的

本测试用于回答三个问题：

1. 三套 VAD 的分段数量是否一致；
2. 哪个模型切得更细、哪个模型更容易形成长段；
3. 分段差异对 Qwen-ASR、CAM++ 和 emotion2vec 的下游任务量有什么影响。

本测试只比较分段行为，不把分段数量多直接当成准确率高。要判断漏检和误检，仍需要人工语音区间标注。

## 二、三套基线定义

### 1. JSON 基线

递归读取每个目录下的 `seaco_paraformer-*.json`，使用 `segments[].bg` 和 `segments[].ed` 作为历史分段结果。

共有 45 个 JSON，且每个都能匹配同名 WAV。

### 2. FunASR 直接基线

使用当前 FunASR FSMN-VAD 模型直接处理同一批 WAV。测试参数与当前服务默认 VAD 配置保持一致：

```toml
vad_speech_noise_thres = 0.6
vad_decibel_thres = -100.0
vad_snr_thres = -100.0
vad_low_volume_filter_enabled = false
vad_max_single_segment_time_ms = 30000
vad_max_end_silence_time_ms = 800
```

本次直接 FunASR 结果使用 CPU。

### 3. FireRedVAD 基线

使用：

```text
/home/zhangs/workspace/asr_nvidia/model/FireRedVAD/VAD
```

使用 FireRedVAD 非流式模型和官方默认参数，运行设备为 CUDA:0。输出时间戳统一转换为秒级 `start_s/end_s`。

## 五、分段粒度结论

整体粒度排序：

```text
JSON 基线：最细
FireRedVAD：中等
FunASR 直接基线：最粗
```

具体表现：

- JSON 比 FunASR 直接结果多 16,586 段；
- FireRedVAD 比 JSON 少 9,415 段；
- FireRedVAD 比 FunASR 直接结果多 7,171 段；
- FireRedVAD 的段长比 JSON 长，但比 FunASR 直接结果短；
- FireRedVAD 的长段尾部最明显，10 秒以上段比例最高；
- FireRedVAD 的覆盖率最低，比 FunASR 直接结果低约 1.15 个百分点，比 JSON 低约 3.78 个百分点。

因此 FireRedVAD 不能简单归类为“更细”或“更粗”。它相对 JSON 更粗，相对直接 FunASR 更细；在本批音频中，它还表现出“更多段、更短段、但覆盖率更低”的组合特征。

## 六、JSON 与直接 FunASR 的差异说明

当前配置中的自定义低分贝过滤是关闭的：

```toml
vad_low_volume_filter_enabled = false
```

直接 FunASR 测试也没有调用 `filter_low_volume_segments()`。所以历史 JSON 与直接 FunASR 的差异不能直接归因于当前新增的低分贝过滤。

更可能的原因包括：

- JSON 生成时的 VAD 参数不同；
- JSON 生成时的 FunASR 或模型版本不同；
- JSON 中的 `segments` 已经过 ASR 链路的合并、拆分或时间轴修正；
- 历史链路对短段、静音和最大段长有额外处理。

所以本测试将 JSON 作为独立的历史输出基线，将直接 FunASR 作为当前运行时基线，不能把两者混为同一个结果。

## 七、对下游模型的影响

如果当前链路按“一个 VAD 段对应一次 Qwen/CAM++/emotion2vec 调用”：

- JSON 基线产生最多下游任务，模型池排队压力最大；
- FunASR 直接基线产生最少任务，但单段更长；
- FireRedVAD 的任务量介于两者之间，但长段和短段同时增加；
- FireRedVAD 的分段边界变化意味着不能按旧分段索引复用 CAM++ 或 emotion2vec 结果；
- 切换 VAD 后必须重新执行完整的 Qwen、CAM++、emotion2vec 链路。

分段数量只能估算任务量，不能证明转写或说话人/情绪结果质量。最终迁移判断还需要人工标注和端到端回归。

## 八、推荐验收方式

在决定是否迁移 FireRedVAD 前，建议从以下样本抽取音频片段人工检查：

1. JSON 段数远高于 FireRedVAD 的综合岩石学样本；
2. FireRedVAD 段数高于 JSON 的储能学术英语样本；
3. FireRedVAD 长段比例明显更高的课堂样本。

对抽样片段标注真实语音区间，计算：

- precision、recall、F1；
- 误报率、漏报率；
- 起点和终点边界误差；
- 对 Qwen-ASR 的文本召回和时间戳影响；
- 对 CAM++/emotion2vec 模型池等待和端到端耗时的影响。

在完成这些验证前，建议继续使用当前 FunASR 作为生产默认 VAD。
